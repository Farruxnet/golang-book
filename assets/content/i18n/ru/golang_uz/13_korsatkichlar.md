# Указатели (pointers)

Указатель (pointer) позволяет обращаться к адресу переменной в памяти. Он даёт возможность изменять одно значение из
разных мест и передавать большую структуру без копирования.

## Операторы `&` и `*`

- `&x` — берёт адрес переменной `x`.
- `*p` — позволяет прочитать или изменить значение, на которое ссылается `p`.
- `*int` — обозначает тип указателя на значение типа `int`.

```go
package main

import "fmt"

func main() {
	x := 10
	p := &x

	fmt.Println("Значение:", x)
	fmt.Println("Через указатель:", *p)
	*p = 20
	fmt.Println("Новое значение:", x)
}
```

Результат:

```text
Значение: 10
Через указатель: 10
Новое значение: 20
```

Тип `p` — `*int`. `*p = 20` не создаёт новый указатель. Это действие изменяет значение `x`, на которое ссылается `p`.
Адрес можно вывести через `&p`, но его точное значение может меняться при каждом запуске программы. Логику программы
не следует привязывать к этому адресу.

## Изменение значения через указатель

Когда обычной переменной присваивается новое значение, меняется только значение этой переменной:

```go
package main

import "fmt"

func main() {
	num := 10
	copied := num

	copied++

	fmt.Println("num:", num)
	fmt.Println("copied:", copied)
}
```

Результат:

```text
num: 10
copied: 11
```

При записи `copied := num` значение `num` копируется в другую переменную. После этого `copied` и `num` — две отдельные
переменные. Изменение `copied` не влияет на `num`.

А с помощью указателя можно обратиться к самой другой переменной:

```go
package main

import "fmt"

func main() {
	num := 10
	p := &num

	*p++

	fmt.Println(num)
}
```

Результат:

```text
11
```

Запись `p := &num` сохраняет адрес переменной `num` в `p`. А `*p` обращается к значению, которое находится по этому
адресу.

Поэтому запись:

```go
*p++
```

означает то же самое, что и:

```go
(*p)++
```

То есть значение, на которое ссылается `p`, увеличивается на единицу.

Здесь есть важное различие:

```go
num := 10
copied := num
```

копирует значение.

А следующий код:

```go
num := 10
p := &num
```

позволяет обращаться к самой `num`.

Указатель нужен не всегда. Если нужны два независимых значения, обычная копия понятнее. Указатель полезен, когда одно
и то же значение нужно видеть или изменять из другого места, и при этом лишняя память не выделяется.

## Указатель и время жизни значения

Пока указатель существует, значение, на которое он ссылается, тоже должно оставаться действительным.

Например:

```go
package main

import "fmt"

func main() {
	var p *int

	{
		num := 13
		p = &num
	}

	fmt.Println(*p)
}
```

Результат:

```text
13
```

Хотя `num` создана во внутреннем блоке, её адрес используется снаружи через `p`.

Компилятор Go определяет, как долго нужно хранить значение. При необходимости время жизни значения управляется в
соответствии с указателем, который его использует.

Программист не освобождает такую память вручную, как в C. Go управляет памятью автоматически.

Эта особенность позволяет безопасно использовать код вроде:

```go
p = &num
```

## Равенство указателей

Два указателя равны, если ссылаются на одну и ту же переменную:

```go
package main

import "fmt"

func main() {
	x := 5

	p1 := &x
	p2 := &x

	y := 5
	p3 := &y

	fmt.Println(p1 == p2)
	fmt.Println(p1 == p3)
}
```

Результат:

```text
true
false
```

`p1` и `p2` хранят адрес одной и той же переменной `x`. Поэтому:

```go
p1 == p2
```

равно `true`.

Значения `x` и `y` одинаковы:

```go
x == y
```

но в памяти это две отдельные переменные.

Поэтому:

```go
p1 == p3
```

равно `false`.

Здесь равенство указателей означает не **равенство значений**, на которые они ссылаются, а то, что они ссылаются на
одно и то же место.

Указатель можно сравнивать с другим указателем подходящего типа или с `nil`.

## Указатель `nil`

Нулевое значение указателя — `nil`.

Например:

```go
package main

import "fmt"

func main() {
	var p *int

	fmt.Println(p)
	fmt.Println(p == nil)
}
```

Результат:

```text
<nil>
true
```

Следующая часть:

```go
var p *int
```

объявляет `p` как указатель типа `*int`, но ему ещё не присвоен адрес ни одной переменной `int`.

Поэтому его значение:

```go
nil
```

Позже ему можно присвоить действительный адрес:

```go
package main

import "fmt"

func main() {
	var p *int

	num := 13
	p = &num

	fmt.Println(p == nil)
	fmt.Println(*p)
}
```

Результат:

```text
false
13
```

Обращаться к значению через указатель `nil` нельзя.

Например:

```go
var p *int
fmt.Println(*p)
```

во время работы программы вызывает `panic`.

```shell
panic: runtime error: invalid memory address or nil pointer dereference
[signal 0xc0000005 code=0x0 addr=0x0 pc=0x7ff781d44b96]
```

Поэтому если указатель может быть `nil`, его сначала нужно проверить:

```go
if p != nil {
    fmt.Println(*p)
}
```

Указатель `nil` позволяет выразить состояние «пока я ни на какое значение не ссылаюсь».

## Создание указателя через `new`

`new(T)` создаёт новую переменную с нулевым значением типа `T` и возвращает указатель типа `*T` на неё.

Например:

```go
package main

import "fmt"

func main() {
	p := new(int)

	fmt.Println(*p)

	*p = 13

	fmt.Println(*p)
}
```

Результат:

```text
0
13
```

Нулевое значение типа `int` — `0`.

Поэтому после записи:

```go
p := new(int)
```

значение:

```go
*p
```

равно `0`.

Затем через:

```go
*p = 13
```

это значение изменено.

Результат `new` — не обычное значение, а указатель:

```go
p := new(int)
```

здесь тип `p`:

```go
*int
```

Часто понятнее создать обычную локальную переменную и взять её адрес:

```go
x := 0
p := &x
```

Этот код даёт результат, похожий на:

```go
p := new(int)
```

`new` и `make` выполняют разные задачи.

`new(T)` даёт указатель типа:

```text
*T
```

А `make` используется только для:

* slice;
* map;
* channel

и создаёт значение, готовое к использованию.

## В Go нет арифметики указателей

В некоторых языках, таких как C и C++, адрес указателя можно изменять арифметическими действиями.

Например, в Go с обычным указателем нельзя написать:

```go
p++
```

или:

```go
p + 1
```

Go не разрешает арифметику указателей в обычном коде.

Это ограничение предотвращает некоторые ошибки, которые могут возникать из-за неправильной работы с адресами памяти.

Для специальных низкоуровневых задач в Go есть пакет `unsafe`. Но в повседневных программах использовать его не нужно.

Использование указателя не означает и того, что значение обязательно хранится в памяти `heap`.

Компилятор Go определяет, где хранится значение, с помощью **escape analysis** (анализа выхода). В зависимости от
ситуации значение может остаться в стеке или быть размещено в `heap`.

Поэтому мнение:

> «Если я использую указатель, код обязательно будет работать быстрее»

неверно.

При выборе указателя в первую очередь учитывается сама задача. А там, где важна скорость работы, правильнее измерять,
а не гадать.

## Slice, map и указатели

Срез — это не сам обычный массив. Он хранит описание, которое ссылается на данные в базовом массиве.

Например:

```go
package main

import "fmt"

func main() {
	numbers := []int{10, 20, 30}
	other := numbers

	other[0] = 100

	fmt.Println(numbers)
	fmt.Println(other)
}
```

Результат:

```text
[100 20 30]
[100 20 30]
```

При записи `other := numbers` копируется описание среза. Но оба `slice` ссылаются на элементы одного и того же
базового массива.

Поэтому изменение:

```go
other[0] = 100
```

видно и через `numbers`. Поэтому для изменения элементов `slice` обычно не нужен указатель на `slice`, такой как
`*[]int`.

С `map` ситуация похожая:

```go
package main

import "fmt"

func main() {
	dict := map[string]int{
		"go": 2009,
	}

	other := dict
	other["python"] = 1991

	fmt.Println(dict)
}
```

`dict` и `other` ссылаются на одни и те же данные map. Поэтому элемент, добавленный через `other`, виден и через
`dict`.

А при использовании `append` со срезом есть отдельный момент:

```go
package main

import "fmt"

func main() {
	numbers := []int{10, 20, 30}

	numbers = append(numbers, 40)

	fmt.Println(numbers)
}
```

В результате `append` получается новое значение среза. Если ёмкости недостаточно, Go может выделить и новый базовый
массив.

Поэтому при работе со срезом обычным способом считается сохранение его нового состояния в виде:

```go
numbers = append(numbers, 40)
```

Там, где собственных возможностей `slice` или `map` достаточно, дополнительный указатель на них может без нужды
усложнить код.

## Когда не стоит использовать указатель?

Указатель даёт возможности, но использовать его для каждого значения не обязательно.

В следующих случаях может хватить обычного значения:

* значение небольшое и копировать его дёшево;
* нужны два независимых значения;
* исходное значение не нужно изменять из другого места;
* состояние `nil` вносит в код ненужную сложность;
* собственное поведение `slice`, `map` или `channel` уже даёт нужную ссылочную семантику.

Например:

```go
x := 10
y := x
```

— нужный способ, если `x` и `y` должны меняться независимо.

Но при записи:

```go
x := 10
p := &x
```

через `p` можно изменить саму `x`.

Превращение каждой переменной в указатель не ускоряет код автоматически. Наоборот, если одно и то же значение может
изменяться из нескольких мест, становится трудно отследить, где изменились данные. Поэтому указатель нужно
использовать тогда, когда нужна его возможность, а не просто из мысли, что «использовать указатели — хорошо».

## Примеры

### 1. Обмен двух значений через указатели

```go
package main

import "fmt"

func main() {
	x, y := 10, 20

	px := &x
	py := &y

	*px, *py = *py, *px

	fmt.Println(x, y)
}
```

Результат:

```text
20 10
```

`px` ссылается на `x`, а `py` — на `y`.

Следующая запись:

```go
*px, *py = *py, *px
```

меняет местами два значения, на которые ссылаются указатели.

Сами указатели не меняются местами. Меняются значения `x` и `y`, на которые они ссылаются.

### 2. Сохранение двух результатов через указатели

```go
package main

import "fmt"

func main() {
	a, b := 17, 5

	var quotient int
	var remainder int

	pQuotient := &quotient
	pRemainder := &remainder

	*pQuotient = a / b
	*pRemainder = a % b

	fmt.Println(quotient, remainder)
}
```

Результат:

```text
3 2
```

`pQuotient` и `pRemainder` ссылаются на две отдельные переменные.

```go
*pQuotient = a / b
```

изменяет значение `quotient`.

```go
*pRemainder = a % b
```

изменяет значение `remainder`.

Этот пример показывает, что несколько указателей могут ссылаться на разные значения и изменять их по отдельности.

### 3. Необязательное значение через `nil`

Иногда нужно различать значение `0` и состояние «значение вообще не задано».

```go
package main

import "fmt"

func main() {
	var discount *int

	if discount == nil {
		fmt.Println("Скидка не задана")
	}

	zero := 0
	discount = &zero

	if discount != nil {
		fmt.Println("Скидка:", *discount)
	}
}
```

Результат:

```text
Скидка не задана
Скидка: 0
```

В первом случае:

```go
discount == nil
```

то есть значение скидки вообще не задано.

Во втором случае указатель существует и ссылается на значение `0`.

Значит:

```text
nil
```

и:

```text
0
```

— не одно и то же состояние.

Указатель позволяет различать состояния «значения нет» и «значение есть, и оно равно нулю».

### 4. Создание значений разных типов через `new`

```go
package main

import "fmt"

func main() {
	active := new(bool)
	name := new(string)

	fmt.Println(*active)
	fmt.Println(*name)

	*active = true
	*name = "Go"

	fmt.Println(*active, *name)
}
```

Сначала:

```go
new(bool)
```

создаёт указатель на `bool` со значением `false`.

```go
new(string)
```

создаёт указатель на `string` со значением пустой строки.

Затем через:

```go
*active = true
*name = "Go"
```

изменяются значения, на которые ссылаются указатели.

### 5. Копия указателя смотрит на то же значение

```go
package main

import "fmt"

func main() {
	num := 5

	first := &num
	second := first

	*second = 25

	fmt.Println(*first, num)
}
```

Результат:

```text
25 25
```

Следующая запись:

```go
second := first
```

не копирует значение `num`.

Здесь копируется значение указателя, то есть адрес.

В результате:

```go
first
```

и:

```go
second
```

ссылаются на одну и ту же переменную `num`.

Поэтому после записи:

```go
*second = 25
```

`25` видно и через `*first`.

### 6. Проверка, смотрят ли указатели на один объект

```go
package main

import "fmt"

func main() {
	num := 13

	a := &num
	b := a

	c := new(int)
	*c = 13

	fmt.Println(a == b)
	fmt.Println(a == c)
}
```

Результат:

```text
true
false
```

`a` и `b` ссылаются на одну и ту же переменную `num`.

Поэтому:

```go
a == b
```

равно `true`.

`c` тоже ссылается на значение `13`, но это другая переменная.

Поэтому:

```go
a == c
```

равно `false`.

Равенство указателей проверяет не равенство значений, на которые они ссылаются, а то, ссылаются ли они на один и тот
же объект.

### 7. Указатель на элемент среза

```go
package main

import "fmt"

func main() {
	numbers := []int{10, 20, 30}

	p := &numbers[1]

	*p = 99

	fmt.Println(numbers)
}
```

Результат:

```text
[10 99 30]
```

Следующая запись:

```go
p := &numbers[1]
```

берёт адрес второго элемента среза.

Затем:

```go
*p = 99
```

изменяет исходное значение этого элемента.

Поэтому изменение видно и в срезе `numbers`.

Здесь есть важный момент. Если позже использовать `append`, для среза может быть выделен новый базовый массив:

```go
numbers = append(numbers, 40, 50, 60)
```

Если создан новый массив, `numbers` начинает ссылаться на него. А ранее взятый `p` может продолжать ссылаться на
элемент прежнего массива.

Поэтому, беря долгоживущие указатели на элементы среза, нужно учитывать, как срез может измениться в дальнейшем.

### 8. Узел связного списка

С помощью указателей можно строить структуры данных, в которых один объект ссылается на другой.

Например:

```go
package main

import "fmt"

type Node struct {
	Value int
	Next  *Node
}

func main() {
	third := &Node{
		Value: 30,
	}

	second := &Node{
		Value: 20,
		Next:  third,
	}

	first := &Node{
		Value: 10,
		Next:  second,
	}

	fmt.Println(first.Value)
	fmt.Println(first.Next.Value)
	fmt.Println(first.Next.Next.Value)
	fmt.Println(first.Next.Next.Next)
}
```

Результат:

```text
10
20
30
<nil>
```

Помимо своего значения каждый `Node` хранит указатель на следующий узел:

```go
Next *Node
```

`first.Next` ссылается на узел `second`.

А `second.Next` ссылается на узел `third`.

В узле `third` значение `Next` не задано. Поскольку нулевое значение указателя `*Node` — `nil`:

```go
third.Next
```

равно `nil`.

Так один объект соединяется с другим через указатель. В этом же состоит одна из главных идей таких структур данных,
как связный список.
