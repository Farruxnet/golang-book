# Программы командной строки и стандартные потоки

Интерфейс командной строки, или **CLI** (`Command Line Interface`), — программа, которой управляют через терминал.

Такая программа обычно:

* принимает аргументы из терминала;
* при необходимости читает дополнительные данные через `stdin`;
* выводит результат в `stdout`;
* пишет сообщения об ошибках и диагностику в `stderr`;
* по завершении возвращает код завершения (exit code).

В Go небольшие и средние CLI-программы можно писать и без внешних библиотек. Для этого достаточно пакетов стандартной библиотеки, таких как `os`, `flag`, `fmt`, `bufio` и `io`.

Например, в следующей команде:

```bash
go run main.go apple pomegranate
```

`apple` и `pomegranate` — аргументы, переданные программе.

Или:

```bash
go run main.go -name Dilshod -count 2
```

здесь `-name` и `-count` — именованные параметры, то есть флаги.

Теперь по шагам посмотрим, как эти данные получают и используют внутри программы на Go.

## Получение аргументов через `os.Args`

Все аргументы, переданные программе на Go через командную строку, хранятся в `os.Args`.

Тип `os.Args`:

```go
[]string
```

то есть это срез из значений `string`.

Важное правило: `os.Args[0]` — не первый аргумент пользователя. Первый элемент обычно хранит имя или путь запущенной программы.

Например:

```go
package main

import (
	"fmt"
	"os"
)

func main() {
	fmt.Println("Программа:", os.Args[0])
	fmt.Println("Аргументы:", os.Args[1:])
}
```

Запускаем программу так:

```bash
go run main.go apple pomegranate
```

Здесь возникает примерно такая ситуация:

```text
os.Args[0]    -> путь выполняемой программы
os.Args[1]    -> "apple"
os.Args[2]    -> "pomegranate"
os.Args[1:]   -> ["apple", "pomegranate"]
```

`os.Args[1:]` — выражение среза. Оно отбрасывает имя программы с индексом `0` и возвращает аргументы, заданные пользователем.

При работе с `go run` есть ещё одна тонкость. Go сначала создаёт временный исполняемый файл, а затем запускает его. Поэтому:

```go
os.Args[0]
```

не обязательно будет `main.go`. Это может быть путь к временному исполняемому файлу.

Поэтому привязывать логику программы к точному значению `os.Args[0]` — плохой подход.

Например, такой проверки нужно избегать:

```go
if os.Args[0] == "main.go" {
	// ...
}
```

Потому что у скомпилированного бинарника или при `go run` это значение может быть другим.

`os.Args` очень удобен для простых позиционных аргументов. Но когда именованных параметров вроде `-name`, `-count`, `-quiet` становится много, разбирать их вручную неудобно. В такой ситуации полезен пакет `flag`.

## Пакет `flag`

Пакет `flag` упрощает объявление и разбор флагов командной строки.

Например:

```go
name := flag.String("name", "guest", "имя пользователя")
count := flag.Int("count", 1, "количество повторений")
quiet := flag.Bool("quiet", false, "не выводить результат")
flag.Parse()
```

Здесь объявлены три флага:

```text
-name
-count
-quiet
```

Их можно использовать так:

```bash
go run main.go -name Dilshod -count 3 -quiet
```

Рассмотрим каждое объявление отдельно.

```go
name := flag.String("name", "guest", "имя пользователя")
```

`flag.String()` принимает три основных аргумента:

```text
"name"              -> имя флага
"guest"             -> значение по умолчанию
"имя пользователя"  -> текст справки
```

В результате функция возвращает `*string`, то есть указатель на `string`.

Поэтому, чтобы потом получить значение, пишут:

```go
*name
```

То же правило действует для `flag.Int()` и `flag.Bool()`:

```go
count := flag.Int("count", 1, "количество повторений")
quiet := flag.Bool("quiet", false, "не выводить результат")
```

Типы этих значений:

```text
name  -> *string
count -> *int
quiet -> *bool
```

Но просто объявить флаги недостаточно.

При вызове:

```go
flag.Parse()
```

пакет `flag` разбирает настоящие аргументы командной строки и обновляет соответствующие значения.

Например, при:

```bash
go run main.go -name Ali -count 5
```

после `flag.Parse()` будет:

```text
*name  == "Ali"
*count == 5
*quiet == false
```

Поскольку `quiet` не указан в команде, сохраняется его значение по умолчанию `false`.

### Позиционные аргументы и `flag.Args()`

Вместе с флагами можно использовать и обычные аргументы.

Например:

```bash
go run main.go -name Ali file1.txt file2.txt
```

После `flag.Parse()` оставшиеся аргументы, которые не являются флагами, можно получить через:

```go
flag.Args()
```

Примерно:

```text
flag.Args() -> ["file1.txt", "file2.txt"]
```

Этот способ полезен в CLI-программах, которые используют флаги и позиционные аргументы вместе.

## Стандартные потоки

Операционная система обычно предоставляет запущенному процессу три стандартных потока:

* `os.Stdin` — стандартный ввод;
* `os.Stdout` — стандартный вывод;
* `os.Stderr` — стандартный поток ошибок.

Эти три потока отделены друг от друга.

В обычном случае их вывод может отображаться в терминале в одном месте. Но через оболочку (shell) их можно перенаправлять в отдельные файлы или другим процессам.

### `os.Stdin`

`os.Stdin` — поток данных, входящих в программу.

Например, пользователь может набрать текст в терминале. Или другая программа может передать данные через `pipe`.

В Go из него можно читать так:

```go
fmt.Fscan(os.Stdin, &value)
```

или, для построчного чтения:

```go
scanner := bufio.NewScanner(os.Stdin)
```

### `os.Stdout`

`os.Stdout` используется для обычных результатов.

Например:

```go
fmt.Fprintln(os.Stdout, "Результат готов")
```

`fmt.Println()` тоже обычно пишет в stdout.

Поэтому:

```go
fmt.Println("Привет")
```

и:

```go
fmt.Fprintln(os.Stdout, "Привет")
```

в обычном случае дают в терминале одинаковый результат.

Преимущество второго варианта в том, что явно видно, в какой `io.Writer` идёт запись. Это удобно и при написании тестов.

### `os.Stderr`

`os.Stderr` используется для ошибок и диагностических сообщений.

Например:

```go
fmt.Fprintln(os.Stderr, "Ошибка: неправильное значение")
```

Почему ошибку не пишут в обычный `stdout`?

Причина в том, что `stdout` и `stderr` можно отдельно управлять через оболочку.

Например, можно записать результат программы в файл:

```bash
./app > result.txt
```

а сообщения об ошибках оставить в терминале.

Или отправить ошибки в отдельный файл:

```bash
./app 2> errors.txt
```

Это особенно важно для скриптов, серверов и CLI-инструментов, которые связаны с другими программами.

Если программа пишет успешный результат в `stdout`, а ошибки — в `stderr`, внешняя программа может их различать.

Например:

```go
fmt.Fprintln(os.Stdout, "Результат готов")
fmt.Fprintln(os.Stderr, "Ошибка: неправильное значение")
```

Обе записи могут появиться в терминале, но они записаны в разные потоки.

## Код завершения

CLI-программа не только выводит текст. По завершении процесса она также возвращает операционной системе числовой **код завершения** (exit code).

Обычно:

```text
0 -> успех
любое значение, кроме 0 -> какая-то ошибка
```

Например, shell-скрипт может по коду завершения определить, успешно ли завершилась предыдущая команда.

В Go, чтобы завершить процесс с определённым кодом, используется:

```go
os.Exit(code)
```

Например:

```go
os.Exit(0)
```

может означать успешное завершение, а:

```go
os.Exit(1)
```

— ошибку.

Смысл конкретных ненулевых значений определяет автор программы.

Например, можно договориться так:

```text
1 -> пользователь задал неправильное значение
2 -> неправильный синтаксис флагов
```

### `os.Exit()` и `defer`

Здесь есть важная тонкость.

**Внимание**

При вызове `os.Exit()` функции, запланированные через `defer`, не выполняются.

Например:

```go
func main() {
    defer fmt.Println("Очистка")

    os.Exit(1)
}
```

Здесь можно ожидать, что выведется:

```text
Очистка
```

Но `os.Exit()` сразу завершает процесс. Поэтому `defer` не срабатывает.

Это может создать проблемы для закрытия файлов, сброса буферов (flush), очистки временных ресурсов и других действий по уборке.

Поэтому распространённый подход такой:

```go
func run() int {
    // Основная работа.
    // Можно использовать defer.

    return 0
}

func main() {
    os.Exit(run())
}
```

Здесь вся основная работа выполняется внутри `run()`.

Поскольку `run()` — обычная функция, при выходе из неё `defer` работают нормально.

Только в самом конце `main()` через:

```go
os.Exit(...)
```

задаёт код завершения процесса.

## Работающий пример CLI

Теперь объединим аргументы, флаги, `stdout`, `stderr` и коды завершения в одной программе.

```go
package main

import (
	"errors"
	"flag"
	"fmt"
	"io"
	"os"
)

func run(args []string, stdout, stderr io.Writer) int {
	fs := flag.NewFlagSet("hello", flag.ContinueOnError)
	fs.SetOutput(stderr)
	name := fs.String("name", "", "имя для приветствия")
	count := fs.Int("count", 1, "количество повторений")
	quiet := fs.Bool("quiet", false, "не выводить результат")

	if err := fs.Parse(args); err != nil {
		return 2
	}
	if *name == "" {
		fmt.Fprintln(stderr, errors.New("нужен параметр -name"))
		return 1
	}
	if *count < 1 {
		fmt.Fprintln(stderr, "ошибка: -count должен быть положительным")
		return 1
	}
	if *quiet {
		return 0
	}
	for i := 0; i < *count; i++ {
		fmt.Fprintf(stdout, "Привет, %s!\n", *name)
	}
	return 0
}

func main() {
	os.Exit(run(os.Args[1:], os.Stdout, os.Stderr))
}
```

Запускаем программу так:

```bash
go run main.go -name Dilshod -count 2
```

Результат:

```text
Привет, Dilshod!
Привет, Dilshod!
```

В этом примере есть несколько важных решений.

Первое:

```go
func run(args []string, stdout, stderr io.Writer) int
```

`run()` не привязана напрямую к глобальным `os.Args`, `os.Stdout` и `os.Stderr`.

Аргументы она получает через параметр:

```go
args []string
```

Потоки вывода тоже передаются через параметры:

```go
stdout io.Writer
stderr io.Writer
```

Это значительно упрощает написание тестов. В тесте вместо настоящего терминала можно передать `bytes.Buffer`.

Например, передав вместо `stdout` буфер в памяти, можно проверить, какой именно текст записала программа.

Следующая важная часть:

```go
fs := flag.NewFlagSet("hello", flag.ContinueOnError)
```

Это создаёт отдельный `FlagSet` вместо флагов по умолчанию глобального пакета `flag`.

С `flag.ContinueOnError` при ошибке разбора флагов процесс автоматически не завершается. Ошибка возвращается из `fs.Parse()`:

```go
if err := fs.Parse(args); err != nil {
	return 2
}
```

Это позволяет CLI-программе самой контролировать, как обрабатываются ошибки.

Затем:

```go
fs.SetOutput(stderr)
```

перенаправляет тексты ошибок и справки, которые выводит `FlagSet`, в переданный нами поток `stderr`.

Значение по умолчанию для `-name` — пустая строка:

```go
name := fs.String("name", "", "имя для приветствия")
```

Поэтому потом можно проверить, было ли оно задано:

```go
if *name == "" {
	fmt.Fprintln(stderr, errors.New("нужен параметр -name"))
	return 1
}
```

Значение `count` тоже проверяется:

```go
if *count < 1 {
	fmt.Fprintln(stderr, "ошибка: -count должен быть положительным")
	return 1
}
```

Здесь синтаксис флага может быть правильным, а значение — неправильным для бизнес-правила.

Например:

```bash
go run main.go -name Ali -count -5
```

`-5` можно прочитать как `int`. Но по требованию программы количество повторений должно быть не меньше `1`. Поэтому это проверяется отдельно.

Если включён `quiet`:

```go
if *quiet {
	return 0
}
```

программа не выводит никакого приветствия, но завершается успешно.

Иначе цикл:

```go
for i := 0; i < *count; i++ {
	fmt.Fprintf(stdout, "Привет, %s!\n", *name)
}
```

выводит результат `count` раз.

В конце:

```go
return 0
```

означает успех.

А `main()` через:

```go
os.Exit(run(os.Args[1:], os.Stdout, os.Stderr))
```

передаёт в `run()` три настоящих значения:

```text
os.Args[1:] -> аргументы пользователя
os.Stdout   -> обычный вывод
os.Stderr   -> поток ошибок
```

Число, возвращённое `run()`, становится кодом завершения процесса.

В этой структуре возвращается:

```text
ошибка синтаксиса флагов -> 2
неправильное значение    -> 1
успех                    -> 0
```

## Примеры

### 1. Получение первого позиционного аргумента

Этот пример показывает получение первого позиционного аргумента пользователя через `os.Args`.

Программа использует аргумент как имя.

```go
package main

import (
	"fmt"
	"os"
)

func main() {
	if len(os.Args) < 2 {
		fmt.Println("Использование: программа ИМЯ")
		return
	}

	name := os.Args[1]
	fmt.Println("Привет,", name)
}
```

Самая важная часть здесь:

```go
if len(os.Args) < 2 {
```

В `os.Args` почти всегда есть хотя бы один элемент:

```text
os.Args[0]
```

— имя или путь программы.

Если пользователь задал аргумент, он находится в:

```text
os.Args[1]
```

Поэтому перед обращением к `os.Args[1]` мы проверяем, что длина среза не меньше `2`.

Если бы этой проверки не было и пользователь не задал аргумент:

```go
name := os.Args[1]
```

обратилась бы к несуществующему индексу, и программа могла бы упасть с panic во время выполнения.

Когда аргумент задан:

```bash
go run main.go Ali
```

результат:

```text
Привет, Ali
```

Главное правило этого примера: `os.Args[0]` относится к программе, а первый аргумент пользователя находится в `os.Args[1]`.

### 2. Просмотр всех позиционных аргументов

Этот пример выводит все позиционные аргументы пользователя с их порядковыми номерами.

```go
package main

import (
	"fmt"
	"os"
)

func main() {
	args := os.Args[1:]
	if len(args) == 0 {
		fmt.Println("Аргументы не заданы")
		return
	}

	for index, value := range args {
		fmt.Printf("%d: %s\n", index+1, value)
	}
}
```

Сначала через:

```go
args := os.Args[1:]
```

отбрасываем имя программы.

Например, при:

```bash
go run main.go apple pomegranate grape
```

получаем:

```text
args == ["apple", "pomegranate", "grape"]
```

Затем:

```go
if len(args) == 0 {
```

проверяет, задал ли пользователь вообще какие-нибудь аргументы.

Если аргументы есть:

```go
for index, value := range args {
```

проходит по элементам среза.

`index` в `range` начинается с `0`:

```text
0 -> apple
1 -> pomegranate
2 -> grape
```

Но пользователю обычно удобнее показывать порядковые номера начиная с `1`. Поэтому используется:

```go
index + 1
```

Результат:

```text
1: apple
2: pomegranate
3: grape
```

Этот пример показывает, что индекс среза и порядковый номер, показываемый пользователю, — не одно и то же.

### 3. Значение флага по умолчанию

В этом примере для флагов `-name` и `-count` задаются значения по умолчанию.

Если пользователь не укажет флаги, программа использует эти значения.

```go
package main

import (
	"flag"
	"fmt"
)

func main() {
	name := flag.String("name", "guest", "имя пользователя")
	count := flag.Int("count", 1, "количество повторений")
	flag.Parse()

	for i := 0; i < *count; i++ {
		fmt.Println("Привет,", *name)
	}
}
```

Здесь из-за:

```go
name := flag.String("name", "guest", "имя пользователя")
```

если `-name` не задан:

```text
*name == "guest"
```

Точно так же из-за:

```go
count := flag.Int("count", 1, "количество повторений")
```

если `-count` не задан:

```text
*count == 1
```

Поэтому результат:

```bash
go run main.go
```

такой:

```text
Привет, guest
```

Если запустить так:

```bash
go run main.go -name Ali -count 3
```

результат:

```text
Привет, Ali
Привет, Ali
Привет, Ali
```

Посмотрим на цикл:

```go
for i := 0; i < *count; i++ {
```

Если `count = 3`:

```text
i = 0 -> выполняется
i = 1 -> выполняется
i = 2 -> выполняется
i = 3 -> i < 3 ложно, цикл заканчивается
```

В результате код выполняется ровно три раза.

Значение по умолчанию `1` для `count` в этом примере логично. Даже если пользователь ничего не задаст, программа поздоровается хотя бы один раз.

### 4. Логический флаг и оставшиеся аргументы

Этот пример показывает получение флага `bool` и оставшихся позиционных аргументов.

```go
package main

import (
	"flag"
	"fmt"
)

func main() {
	upper := flag.Bool("upper", false, "включить режим заглавных букв")
	flag.Parse()

	fmt.Println("Режим заглавных букв:", *upper)
	fmt.Println("Оставшиеся аргументы:", flag.Args())
}
```

Значение по умолчанию для `upper`:

```go
false
```

Это значит, что режим по умолчанию выключен.

Если пользователь запустит:

```bash
go run main.go
```

получится такой результат:

```text
Режим заглавных букв: false
Оставшиеся аргументы: []
```

Если запустить так:

```bash
go run main.go -upper apple pomegranate
```

то:

```text
*upper == true
```

`flag.Parse()` разбирает `-upper` как флаг.

А оставшиеся аргументы:

```text
apple
pomegranate
```

получают через:

```go
flag.Args()
```

Результат примерно такой:

```text
Режим заглавных букв: true
Оставшиеся аргументы: [apple pomegranate]
```

Этот пример показывает, как разделить флаги и позиционные аргументы в одной CLI-программе.

### 5. Запись значения в существующую переменную

`flag.String()` возвращает новое значение `*string`.

Но иногда удобнее записать значение в заранее объявленную переменную. Для этого есть `flag.StringVar()`.

```go
package main

import (
	"flag"
	"fmt"
)

func main() {
	var city string
	flag.StringVar(&city, "city", "Ташкент", "название города")
	flag.Parse()

	fmt.Println("Город:", city)
}
```

Сначала пишется:

```go
var city string
```

Нулевое значение типа `string` — пустая строка:

```text
""
```

Затем вызывается:

```go
flag.StringVar(&city, "city", "Ташкент", "название города")
```

Здесь `&city` — адрес переменной `city`.

При разборе пакет `flag` записывает значение прямо в эту переменную.

Если пользователь запустит:

```bash
go run main.go
```

используется значение по умолчанию:

```text
Город: Ташкент
```

При:

```bash
go run main.go -city Самарканд
```

выводится:

```text
Город: Самарканд
```

С `flag.String()` пришлось бы написать:

```go
city := flag.String(...)
```

и потом использовать:

```go
*city
```

А `StringVar()` обновляет существующую переменную. Поэтому потом используется напрямую:

```go
city
```

### 6. Просмотр только явно заданных флагов

Иногда программе нужно знать, какие флаги пользователь действительно написал.

Наличие значения по умолчанию не означает, что флаг был задан в команде.

В такой ситуации используется `flag.Visit()`.

```go
package main

import (
	"flag"
	"fmt"
)

func main() {
	flag.String("name", "guest", "имя пользователя")
	flag.Int("count", 1, "количество повторений")
	flag.Bool("quiet", false, "тихий режим")
	flag.Parse()

	fmt.Println("Явно заданные флаги:")
	flag.Visit(func(item *flag.Flag) {
		fmt.Printf("-%s=%s\n", item.Name, item.Value.String())
	})
}
```

В этой программе три флага:

```text
-name
-count
-quiet
```

Но `flag.Visit()` видит не все, а только те, что пользователь явно написал в команде.

Например, при:

```bash
go run main.go -name Ali -quiet
```

выводится:

```text
-name=Ali
-quiet=true
```

А `count`, хотя и имеет значение по умолчанию:

```text
1
```

в команде не написан. Поэтому в `flag.Visit()` он не попадает.

Эта разница может быть полезна в системах конфигурации.

Например, значение может прийти в программу из файла конфигурации, из переменной окружения и из флага CLI. Тогда может быть важно знать, задал ли пользователь флаг явно через CLI или использовалось значение по умолчанию.

### 7. Чтение одного значения из стандартного ввода

В этом примере через `fmt.Fscan()` из `stdin` читается одно значение.

```go
package main

import (
	"fmt"
	"os"
)

func main() {
	var product string
	fmt.Fprint(os.Stdout, "Название товара: ")

	if _, err := fmt.Fscan(os.Stdin, &product); err != nil {
		fmt.Fprintln(os.Stderr, "Ошибка: название не прочитано")
		return
	}

	fmt.Fprintln(os.Stdout, "Принято:", product)
}
```

Сначала через:

```go
var product string
```

создаётся пустая `string`.

Затем:

```go
fmt.Fprint(os.Stdout, "Название товара: ")
```

выводит пользователю приглашение.

Основное чтение выполняется через:

```go
fmt.Fscan(os.Stdin, &product)
```

Здесь важна причина передачи `&product`.

`Fscan()` должна записать прочитанное значение в переменную `product`. Для этого ей нужен адрес переменной.

Если чтение не удалось, выполняется условие:

```go
if _, err := fmt.Fscan(...); err != nil {
```

и ошибка записывается в `stderr` через:

```go
fmt.Fprintln(os.Stderr, "Ошибка: название не прочитано")
```

В успешном случае работает:

```go
fmt.Fprintln(os.Stdout, "Принято:", product)
```

В эту программу данные можно вводить вручную в терминале.

Но `stdin` — это не только клавиатура.

Например, в команде:

```bash
echo notebook | go run main.go
```

вывод `echo` через pipe передаётся в `stdin` следующей программы.

Поток примерно такой:

```text
echo
  |
  v
"notebook"
  |
  v
stdin
  |
  v
fmt.Fscan()
  |
  v
product
```

В результате значение `product`:

```text
notebook
```

### 8. Построчное чтение стандартного ввода

При работе с многострочным вводом удобен `bufio.Scanner`.

В этом примере каждая строка из `stdin` выводится с порядковым номером.

```go
package main

import (
	"bufio"
	"fmt"
	"os"
)

func main() {
	scanner := bufio.NewScanner(os.Stdin)
	lineNumber := 1

	for scanner.Scan() {
		fmt.Fprintf(os.Stdout, "%d: %s\n", lineNumber, scanner.Text())
		lineNumber++
	}

	if err := scanner.Err(); err != nil {
		fmt.Fprintln(os.Stderr, "Ошибка чтения:", err)
	}
}
```

Сначала через:

```go
scanner := bufio.NewScanner(os.Stdin)
```

создаётся сканер, работающий с `stdin`.

По умолчанию `Scanner` разбивает ввод на строки.

Затем:

```go
lineNumber := 1
```

задаёт номер первой показываемой строки.

Цикл:

```go
for scanner.Scan() {
```

каждый раз пытается прочитать следующую строку.

Если следующий токен, в данном случае строка, существует:

```go
scanner.Scan()
```

возвращает `true`.

Текст строки получают через:

```go
scanner.Text()
```

Например, если ввод:

```text
apple
pomegranate
grape
```

вывод будет:

```text
1: apple
2: pomegranate
3: grape
```

После каждой итерации:

```go
lineNumber++
```

увеличивает номер строки на единицу.

Завершение цикла не всегда означает ошибку.

`Scan()` возвращает `false` и тогда, когда ввод закончился обычным образом.

Поэтому после цикла через:

```go
if err := scanner.Err(); err != nil {
```

проверяется, не остановился ли сканер из-за ошибки.

Это важно, потому что по одному только `Scan() == false` нельзя отличить конец ввода от ошибки чтения.

> **Замечание**
>
> У `bufio.Scanner` есть ограничение по умолчанию для очень больших токенов. Если нужно читать очень длинные строки, может понадобиться увеличить буфер сканера или использовать другой способ, например `bufio.Reader`.

### 9. Запись результата и ошибки в разные потоки

Этот пример показывает совместное использование `stdout`, `stderr` и кода завершения.

Если есть аргумент, результат пишется в `stdout`.

Если аргумента нет, сообщение об использовании пишется в `stderr` и возвращается ненулевой код завершения.

```go
package main

import (
	"fmt"
	"os"
)

func run(args []string) int {
	if len(args) == 0 {
		fmt.Fprintln(os.Stderr, "Использование: программа ТЕКСТ")
		return 1
	}

	fmt.Fprintln(os.Stdout, "Результат:", args[0])
	return 0
}

func main() {
	os.Exit(run(os.Args[1:]))
}
```

`main()` через:

```go
os.Args[1:]
```

отбрасывает имя программы.

Поэтому `run()` получает только аргументы пользователя.

Если:

```go
len(args) == 0
```

значит, пользователь не задал нужный аргумент.

Тогда:

```go
fmt.Fprintln(os.Stderr, "Использование: программа ТЕКСТ")
```

пишет сообщение об ошибке или использовании в `stderr`.

Затем:

```go
return 1
```

обозначает состояние ошибки.

Если аргумент есть:

```go
fmt.Fprintln(os.Stdout, "Результат:", args[0])
```

выводит обычный результат в `stdout`.

Затем:

```go
return 0
```

обозначает успех.

Например, вывод:

```bash
go run main.go hello
```

такой:

```text
Результат: hello
```

В этом примере чётко разделены три канала:

```text
обычный результат -> stdout
сообщение об ошибке -> stderr
состояние         -> код завершения
```

В CLI-программах такое разделение полезно. Ведь другая программа может обрабатывать данные из stdout, а диагностику из stderr показывать отдельно.

### 10. CLI с отдельным `FlagSet`

В этом примере мы не используем глобальное состояние `flag`.

Для разбора аргументов создаётся отдельный `FlagSet`. А аргументы и потоки вывода передаются функции `run()` как параметры.

```go
package main

import (
	"flag"
	"fmt"
	"io"
	"os"
)

func run(args []string, stdout, stderr io.Writer) int {
	fs := flag.NewFlagSet("greet", flag.ContinueOnError)
	fs.SetOutput(stderr)
	name := fs.String("name", "guest", "имя пользователя")

	if err := fs.Parse(args); err != nil {
		return 2
	}

	fmt.Fprintln(stdout, "Привет,", *name)
	return 0
}

func main() {
	code := run(os.Args[1:], os.Stdout, os.Stderr)
	os.Exit(code)
}
```

Главная часть:

```go
fs := flag.NewFlagSet("greet", flag.ContinueOnError)
```

Это создаёт новый независимый `FlagSet`.

Вместо глобальных:

```go
flag.String(...)
flag.Parse()
```

теперь используются:

```go
fs.String(...)
fs.Parse(...)
```

Этот подход особенно удобен в тестах и в программах с несколькими командами.

Например, если в большой CLI есть подкоманды вроде:

```text
app create
app delete
app list
```

для каждой можно создать отдельный `FlagSet`.

Следующая строка:

```go
fs.SetOutput(stderr)
```

перенаправляет диагностические сообщения и сообщения разбора `FlagSet` в переданный нами поток `stderr`.

Флаг `name`:

```go
name := fs.String("name", "guest", "имя пользователя")
```

использует в качестве значения по умолчанию:

```text
guest
```

Поэтому:

```bash
go run main.go
```

тоже не ошибка.

Результат:

```text
Привет, guest
```

Если запустить так:

```bash
go run main.go -name Ali
```

выводится:

```text
Привет, Ali
```

Если при разборе возникнет ошибка, сработает:

```go
if err := fs.Parse(args); err != nil {
	return 2
}
```

Поскольку выбран `flag.ContinueOnError`, `FlagSet` сам процесс не завершает. Он возвращает ошибку через `Parse()`.

Поэтому `run()` может обработать состояние ошибки как код завершения.

В конце пишется:

```go
code := run(os.Args[1:], os.Stdout, os.Stderr)
os.Exit(code)
```

В этой структуре `main()` очень маленькая.

Её задача — только подключить реальные ресурсы операционной системы к `run()`:

```text
os.Args[1:] -> аргументы
os.Stdout   -> stdout
os.Stderr   -> stderr
```

и превратить возвращённый код завершения в результат процесса.

А основная логика программы остаётся внутри `run()`. Поэтому её проще тестировать отдельно.
