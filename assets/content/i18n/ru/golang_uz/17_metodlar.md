# Методы в Go

**Метод** — функция, привязанная к определённому типу.

Обычная функция работает сама по себе. А метод выполняет действие над определённым значением или типом.

Например, если у нас есть тип `Rectangle`, для вычисления его площади можно написать метод `Area()`:

```go
rectangle.Area()
```

Здесь `Area()` — метод, принадлежащий именно типу `Rectangle`.

Главное отличие метода от обычной функции в том, что перед именем функции пишется **получатель (receiver)**.

Например:

```go
func (r Rectangle) Area() float64 {
    return r.Width * r.Height
}
```

Здесь:

* `Area` — имя метода;
* `Rectangle` — тип, к которому привязан метод;
* `r` — получатель, то есть значение, с которым работает метод.

По получателю мы понимаем, к какому типу относится метод.

## Получатель-значение (value receiver)

Сначала рассмотрим простой пример:

```go
package main

import "fmt"

type Rectangle struct {
	Width  float64
	Height float64
}

func (r Rectangle) Area() float64 {
	return r.Width * r.Height
}

func main() {
	rectangle := Rectangle{Width: 5, Height: 3}
	fmt.Println("Площадь:", rectangle.Area())
}
```

Результат:

```text
Площадь: 15
```

В этом коде в части:

```go
func (r Rectangle) Area() float64
```

фрагмент:

```go
(r Rectangle)
```

является получателем.

Он показывает, что этот метод принадлежит типу `Rectangle`.

Поэтому метод можно вызвать так:

```go
rectangle.Area()
```

Здесь значение `rectangle` передаётся получателю `r` внутри метода.

Но есть важный момент: `Rectangle` — не указатель.

```go
(r Rectangle)
```

Это называется **получателем-значением** (value receiver).

При использовании получателя-значения метод работает с копией значения получателя.

Например:

```go
func (r Rectangle) Area() float64 {
    return r.Width * r.Height
}
```

`Area()` только читает значения `Width` и `Height`. Он не изменяет данные внутри `Rectangle`.

Поэтому здесь удобно использовать получатель-значение.

Обычно получатель-значение подходит в таких случаях:

* метод только читает значение;
* значение не нужно изменять;
* тип небольшой;
* копирование типа не требует больших затрат.

Метод нельзя привязать к любому типу.

В Go метод можно привязать только к **именованному типу, объявленному в том же пакете**.

Например, из своего пакета нельзя добавить новый метод к типу:

```go
time.Time
```

который находится в другом пакете.

То есть так сделать нельзя:

```go
func (t time.Time) MyMethod() {
}
```

Причина в том, что тип `time.Time` объявлен не в нашем пакете.

## Добавление метода к простому типу

Методы пишутся не только для `struct`.

Методы можно привязывать и к другим именованным типам, объявленным в нашем пакете.

Например:

```go
package main

import "fmt"

type Celsius float64

func (c Celsius) Fahrenheit() float64 {
	return float64(c)*9/5 + 32
}

func main() {
	temperature := Celsius(25)
	fmt.Println(temperature.Fahrenheit())
}
```

Результат:

```text
77
```

Здесь через:

```go
type Celsius float64
```

создан новый тип `Celsius`.

В его основе лежит `float64`, но для Go `Celsius` — отдельный именованный тип.

Поэтому к нему можно добавить метод:

```go
func (c Celsius) Fahrenheit() float64 {
    return float64(c)*9/5 + 32
}
```

Теперь у значения `Celsius` можно вызвать метод:

```go
temperature.Fahrenheit()
```

Это очень удобно.

Например, обычное значение:

```go
float64
```

говорит только о том, что это число.

А создав отдельный тип:

```go
Celsius
```

мы выразили и то, что это значение — **температура**.

Кроме того, к нему можно добавить методы, связанные с температурой.

Но не путайте это со следующей записью:

```go
type Celsius = float64
```

Она не создаёт новый тип.

Она лишь создаёт другое имя для `float64`, то есть **псевдоним** (alias).

Поэтому к псевдониму нельзя привязать отдельный метод.

Разница:

```go
type Celsius float64
```

создаёт новый тип.

```go
type Celsius = float64
```

лишь создаёт другое имя для `float64`.

## Получатель-указатель (pointer receiver)

Некоторые методы не только читают значение. Им нужно изменить исходное значение.

В таком случае используется **получатель-указатель** (pointer receiver).

Например:

```go
package main

import "fmt"

type Account struct {
	Balance int64
}

func (a *Account) Deposit(amount int64) error {
	if a == nil {
		return fmt.Errorf("account равен nil")
	}

	if amount <= 0 {
		return fmt.Errorf("amount должен быть положительным")
	}

	a.Balance += amount
	return nil
}

func main() {
	account := Account{Balance: 100_000}

	if err := account.Deposit(25_000); err != nil {
		fmt.Println("Ошибка:", err)
		return
	}

	fmt.Println(account.Balance)
}
```

Результат:

```text
125000
```

Обратите внимание на получателя метода:

```go
func (a *Account) Deposit(amount int64) error
```

Получатель записан в виде:

```go
(a *Account)
```

`*Account` означает указатель на значение `Account`.

Значит, методу `Deposit()` передаётся не копия значения `Account`, а указатель на его адрес.

Поэтому метод может изменить исходное значение `Account`:

```go
a.Balance += amount
```

Сначала баланс был:

```text
100000
```

Метод был вызван:

```go
account.Deposit(25_000)
```

В результате баланс внутри исходного `account` изменился:

```text
125000
```

Если бы этот метод был написан с получателем-значением:

```go
func (a Account) Deposit(amount int64)
```

`a` была бы лишь копией `account`.

Изменение внутри метода не повлияло бы на исходное значение `account`.

У получателя-указателя есть ещё одно удобство.

Мы написали:

```go
a.Balance
```

На самом деле `a` — указатель типа:

```go
*Account
```

Теоретически к полю можно обратиться так:

```go
(*a).Balance
```

Но Go делает это автоматически.

Поэтому достаточно написать:

```go
a.Balance
```

Go понимает, что мы обращаемся к полю структуры через указатель.

Ещё один интересный момент:

```go
account.Deposit(25_000)
```

Здесь `account` — не указатель.

Это обычное значение:

```go
Account
```

Но метод требует получателя типа:

```go
*Account
```

Go и это в большинстве случаев решает автоматически.

Если адрес значения можно взять, вызов:

```go
account.Deposit(25_000)
```

фактически приводится к:

```go
(&account).Deposit(25_000)
```

Поэтому писать `&account` вручную каждый раз не нужно.

### Получатель-указатель `nil`

У получателя-указателя есть ещё одна особенность: получатель может быть `nil`.

Например:

```go
var account *Account
```

Здесь `account` имеет значение:

```go
nil
```

Несмотря на это, вызвать метод с получателем-указателем технически можно:

```go
account.Deposit(1000)
```

Поэтому при необходимости внутри метода нужно проверять `nil`:

```go
if a == nil {
    return fmt.Errorf("account равен nil")
}
```

Именно так сделано в методе `Deposit()` выше.

Если получатель равен `nil`, метод не обращается к полям структуры и возвращает ошибку.

Это предотвращает в программе ошибку времени выполнения вроде `nil pointer dereference`.

## Управление состоянием через методы

Одно из важных преимуществ методов — хранение правил изменения данных в одном месте.

Например, представим банковский счёт.

Баланс можно хранить открыто:

```go
type Account struct {
    Balance int64
}
```

В таком случае внешний код может записать любое значение:

```go
account.Balance = -999999
```

А это может не соответствовать бизнес-правилам.

Вместо этого поле можно скрыть от кода за пределами пакета и управлять им через методы:

```go
package main

import (
	"errors"
	"fmt"
)

type Account struct {
	balance int64
}

func (a *Account) Deposit(amount int64) error {
	if amount <= 0 {
		return errors.New("сумма должна быть положительной")
	}

	a.balance += amount
	return nil
}

func (a Account) Balance() int64 {
	return a.balance
}

func main() {
	account := Account{}

	if err := account.Deposit(50_000); err != nil {
		fmt.Println("Ошибка:", err)
		return
	}

	fmt.Println(account.Balance())
}
```

Результат:

```text
50000
```

Здесь:

```go
balance int64
```

начинается со строчной буквы.

В Go имена, начинающиеся со строчной буквы, не экспортируются за пределы пакета.

Значит, код из другого пакета не может напрямую обратиться к значению через:

```go
account.balance
```

Чтобы изменить баланс, нужно использовать метод:

```go
account.Deposit(...)
```

А внутри метода есть проверка:

```go
if amount <= 0 {
    return errors.New("сумма должна быть положительной")
}
```

Поэтому ввод неправильного значения можно предотвратить в одном месте.

Для чтения баланса используется метод:

```go
account.Balance()
```

В результате:

* то, как можно изменять значение, хранится в `Deposit()`;
* то, как получать значение, определяет `Balance()`;
* бизнес-правила не нужно повторять в разных местах программы.

Такой подход упрощает управление кодом.

## Способы вызова метода

Методы можно использовать несколькими способами.

Самый простой способ — вызвать метод у значения.

Например:

```go
area := rectangle.Area()
```

Обычно это самая распространённая форма.

Но Go позволяет получить метод и как **значение-функцию**.

У этого есть две важные формы:

* method value;
* method expression.

### Method value

Рассмотрим следующий пример:

```go
package main

import "fmt"

type Counter struct {
	value int
}

func (c *Counter) Add(n int) {
	c.value += n
}

func main() {
	counter := &Counter{}

	add := counter.Add

	add(3)
	add(2)

	fmt.Println(counter.value)
}
```

Результат:

```text
5
```

Обычно метод можно вызвать так:

```go
counter.Add(3)
```

Но в этом примере через:

```go
add := counter.Add
```

мы сохранили метод в переменную.

Это называется **method value**.

Важно, что значение `counter` сохраняется вместе с методом.

То есть переменная:

```go
add
```

уже знает, с каким `Counter` она должна работать.

Поэтому при вызове:

```go
add(3)
```

передавать `counter` в качестве аргумента снова не нужно.

Затем при вызове:

```go
add(2)
```

изменяется тот же самый `counter`.

В результате получается:

```text
5
```

### Method expression

Method expression работает иначе.

Например:

```go
add := (*Counter).Add
add(counter, 5)
```

Здесь:

```go
(*Counter).Add
```

не привязывает метод к конкретному значению `counter`.

Наоборот, метод берётся в виде, похожем на обычную функцию.

Поэтому получателя мы передаём сами в качестве первого аргумента:

```go
add(counter, 5)
```

Здесь:

```go
counter
```

— получатель.

```go
5
```

— аргумент `n` метода `Add()`.

Method expression полезен, когда один и тот же метод нужно использовать с разными значениями.

Например:

```go
counter1 := &Counter{}
counter2 := &Counter{}

add := (*Counter).Add

add(counter1, 5)
add(counter2, 10)
```

Здесь одна функция `add` используется с двумя разными `Counter`.

## Автоматическое взятие адреса и разыменование

При вызове методов Go немного упрощает работу с указателями.

Например, следующие два вызова в большинстве случаев работают одинаково:

```go
account := Account{}

account.Deposit(1000)
(&account).Deposit(1000)
```

Представим, что `Deposit()` написан с получателем-указателем:

```go
func (a *Account) Deposit(amount int64)
```

В первом вызове:

```go
account.Deposit(1000)
```

`account` — обычное значение `Account`.

А метод требует получателя типа:

```go
*Account
```

Но адрес переменной `account` взять можно.

Поэтому Go автоматически приводит его к виду:

```go
&account
```

В результате нам не нужно каждый раз писать:

```go
(&account).Deposit(1000)
```

Достаточно простого:

```go
account.Deposit(1000)
```

Бывает и обратное.

Предположим, `Balance()` написан с получателем-значением:

```go
func (a Account) Balance() int64 {
    return a.balance
}
```

А у нас есть указатель:

```go
accountPointer := &account
```

Несмотря на это, можно вызвать:

```go
fmt.Println(accountPointer.Balance())
```

Go автоматически разыменовывает указатель и вызывает метод.

Здесь Go сам выполняет за нас нужную операцию `*` или `&`.

Но нужно различать одну важную вещь:

> То, что Go автоматически применяет `&` или `*` при вызове метода, не означает, что наборы методов типов `Account` и `*Account` одинаковы.

Эта разница особенно важна при работе с интерфейсами.

## Выбор получателя

Один из самых частых вопросов при написании метода:

> Использовать получатель-значение или получатель-указатель?

Одного универсального правила для ответа нет.

Но есть несколько практических правил.

### Когда используется получатель-указатель?

В следующих случаях выбор получателя-указателя обычно правильный.

#### Метод изменяет значение

Например:

```go
func (a *Account) Deposit(amount int64) {
    a.Balance += amount
}
```

Этот метод должен изменить исходное значение `Account`.

Поэтому нужен получатель-указатель.

#### Структура большая

При использовании получателя-значения значение структуры копируется.

Для небольших структур это обычно не проблема.

Но если структура очень большая, копирование при каждом вызове метода может стать лишними затратами.

В таком случае удобен получатель-указатель.

#### Структура содержит поле, которое нельзя копировать

Например, копировать структуры, использующие такие значения, как:

```go
sync.Mutex
```

не рекомендуется.

Поэтому у таких типов обычно используют получатель-указатель.

#### Другие методы используют получатель-указатель

Если у типа много методов, при выборе получателя полезна последовательность.

Например:

```go
func (a *Account) Deposit(...)
func (a *Account) Withdraw(...)
func (a *Account) Balance(...)
```

Когда у одного метода получатель-указатель, а у другого — получатель-значение, это иногда затрудняет понимание кода.

Поэтому хорошая практика — по возможности последовательно выбирать получателя для одного типа.

### Когда используется получатель-значение?

Получатель-значение удобен для небольших типов, похожих на значения.

Например:

```go
type Celsius float64
```

Это значение небольшое, и изменять его не нужно.

Поэтому:

```go
func (c Celsius) Fahrenheit() float64
```

— хороший пример получателя-значения.

Но о получателе-значении есть одно важное замечание.

Предположим, внутри структуры есть:

```go
map
```

или:

```go
slice
```

Даже если сама структура копируется, базовые данные `map` или среза могут храниться в другом месте.

Поэтому метод с получателем-значением тоже может изменить данные внутри `map` или среза.

Например, одного правила:

> «Если метод что-то изменяет, я использую получатель-указатель»

не всегда достаточно.

При выборе получателя учитываются и то, какие данные хранит тип, и его семантика.

## Набор методов и связь с интерфейсами

В Go у каждого типа есть **набор методов** (method set).

Это особенно важно при работе с интерфейсами.

Предположим, у нас есть тип:

```go
type T struct{}
```

Если метод написан с получателем-значением:

```go
func (t T) Method()
```

этот метод входит в набор методов `T`.

А `*T` может использовать и методы с получателем-значением.

То есть, если говорить проще:

* в наборе методов `T` есть методы с получателем `T`;
* в наборе методов `*T` есть методы с получателями `T` и `*T`.

Это влияет на реализацию интерфейса.

Например:

```go
package main

import "fmt"

type Incrementer interface {
	Increment()
}

type Counter int

func (c *Counter) Increment() {
	*c++
}

func run(value Incrementer) {
	value.Increment()
}

func main() {
	var counter Counter

	run(&counter)

	fmt.Println(counter)
}
```

Результат:

```text
1
```

Здесь интерфейс:

```go
type Incrementer interface {
    Increment()
}
```

говорит, что нужен тип с методом `Increment()`.

Метод для `Counter` написан так:

```go
func (c *Counter) Increment()
```

Обратите внимание, что получатель:

```go
*Counter
```

Значит, `Increment()` — метод с получателем-указателем.

Поэтому:

```go
*Counter
```

реализует интерфейс `Incrementer`.

Следующий код работает:

```go
run(&counter)
```

Потому что тип:

```go
&counter
```

это:

```go
*Counter
```

Но:

```go
run(counter)
```

не компилируется.

Причина в том, что в собственном наборе методов `Counter` нет:

```go
Increment()
```

Метод объявлен только для:

```go
*Counter
```

Здесь нужно запомнить ещё одно важное различие.

В предыдущем разделе мы видели, что такой вызов работает:

```go
counter.Increment()
```

Если адрес `counter` можно взять, Go при вызове метода может автоматически привести его к виду:

```go
(&counter).Increment()
```

Но при проверке интерфейса такое автоматическое преобразование не выполняется.

Соответствие интерфейсу проверяется на этапе компиляции на основе **набора методов** типа.

Поэтому нельзя путать следующие две ситуации:

```go
counter.Increment()
```

и:

```go
run(counter)
```

В первой Go может автоматически подстроить вызов метода.

Во второй же через набор методов проверяется, реализует ли тип `Counter` интерфейс.

## Выбор имени получателя

У получателя, как и у обычной переменной, есть имя.

Например:

```go
func (a Account) Balance() int64
```

Здесь имя получателя:

```go
a
```

Или:

```go
func (c *Counter) Increment()
```

здесь получатель:

```go
c
```

В коде на Go имя получателя обычно состоит из одной-двух букв имени типа.

Например, для:

```go
type Account struct{}
```

можно использовать:

```go
a
```

Для:

```go
type Counter struct{}
```

можно использовать:

```go
c
```

В Go не принято использовать, как в некоторых других языках, имена:

```text
this
```

или:

```text
self
```

Например, вместо:

```go
func (this Account) Balance() int64
```

следующая запись ближе к стилю Go:

```go
func (a Account) Balance() int64
```

Ещё одна рекомендация — использовать одно и то же имя получателя во всех методах одного типа.

Например:

```go
func (a *Account) Deposit(amount int64) {}
func (a *Account) Withdraw(amount int64) {}
func (a *Account) Balance() int64 {}
```

Можно использовать `a` в одном методе, `acc` в другом и `account` в третьем, но одинаковое имя помогает быстрее читать код.

## Примеры

### 1. Вычисление с получателем-значением

```go
package main

import "fmt"

type Box struct {
	Width  float64
	Height float64
}

func (b Box) Area() float64 {
	return b.Width * b.Height
}

func main() {
	b := Box{
		Width:  8,
		Height: 5,
	}

	fmt.Println(b.Area())
}
```

В этом примере:

```go
func (b Box) Area() float64
```

использует получатель-значение.

Метод `Area()` не изменяет значения внутри `Box`.

Он только читает значения:

```go
b.Width
```

и:

```go
b.Height
```

и вычисляет площадь.

Поэтому здесь получатель-указатель не нужен.

При вызове метода значение `Box` передаётся получателю как копия:

```go
b.Area()
```

### 2. Обновление значения с получателем-указателем

```go
package main

import "fmt"

type Tally struct {
	Count int
}

func (t *Tally) Inc() {
	t.Count++
}

func main() {
	t := Tally{}

	t.Inc()
	t.Inc()

	fmt.Println(t.Count)
}
```

Здесь задача метода `Inc()` — изменить значение внутри `Tally`.

Поэтому получатель записан в виде:

```go
(t *Tally)
```

Это получатель-указатель.

Внутри метода:

```go
t.Count++
```

изменяет исходное значение `t`.

После первого вызова будет:

```text
1
```

после второго:

```text
2
```

Мы вызвали метод так:

```go
t.Inc()
```

На самом деле метод требует получателя `*Tally`.

Но поскольку адрес переменной `t` можно взять, Go автоматически приводит вызов к виду:

```go
(&t).Inc()
```

### 3. Добавление метода к простому именованному типу

```go
package main

import "fmt"

type Celsius float64

func (c Celsius) Fahrenheit() float64 {
	return float64(c)*9/5 + 32
}

func main() {
	temperature := Celsius(25)

	fmt.Println(temperature.Fahrenheit())
}
```

Метод не обязательно писать только для `struct`.

В этом примере через:

```go
type Celsius float64
```

на основе `float64` создан новый тип `Celsius`.

Теперь для `Celsius` можно написать отдельный метод:

```go
func (c Celsius) Fahrenheit() float64
```

Метод переводит значение в градусах Цельсия в градусы Фаренгейта.

Поэтому код вида:

```go
temperature.Fahrenheit()
```

читается понятно.

Этот способ позволяет придать смысл и связанное с ним поведение даже простым значениям.

### 4. Проверка значения через метод

```go
package main

import "fmt"

type Age int

func (a Age) Valid() bool {
	return a >= 0 && a <= 150
}

func main() {
	age := Age(24)

	fmt.Println(age.Valid())
}
```

В этом примере через:

```go
type Age int
```

создан отдельный тип для возраста.

Затем написан метод, проверяющий, находится ли возраст в допустимом диапазоне:

```go
func (a Age) Valid() bool {
    return a >= 0 && a <= 150
}
```

Теперь не нужно в каждом месте программы писать проверку:

```go
age >= 0 && age <= 150
```

Вместо этого можно вызвать:

```go
age.Valid()
```

Правило проверки хранится в собственном методе типа.

Если правило позже изменится, достаточно изменить только один метод.

### 5. Обновление, контролируемое методом

```go
package main

import "fmt"

type Wallet struct {
	Balance int
}

func (w *Wallet) Withdraw(amount int) bool {
	if amount <= 0 || amount > w.Balance {
		return false
	}

	w.Balance -= amount
	return true
}

func main() {
	w := Wallet{Balance: 100}

	fmt.Println(w.Withdraw(30), w.Balance)
}
```

В этом примере для снятия денег с кошелька написан метод `Withdraw()`.

Метод сначала проверяет заданную сумму:

```go
if amount <= 0 || amount > w.Balance {
    return false
}
```

В двух случаях деньги не снимаются:

* сумма равна `0` или меньше;
* сумма больше баланса.

Если значение правильное, баланс уменьшается через:

```go
w.Balance -= amount
```

Затем возвращается:

```go
true
```

Поэтому по результату метода можно узнать, выполнена ли операция.

Самое важное — если задана неправильная сумма, состояние `Wallet` не меняется.

### 6. Проверка получателя `nil`

```go
package main

import "fmt"

type Node struct {
	Value int
}

func (n *Node) ValueOrZero() int {
	if n == nil {
		return 0
	}

	return n.Value
}

func main() {
	var node *Node

	fmt.Println(node.ValueOrZero())
}
```

В этом примере указатель объявлен через:

```go
var node *Node
```

Но ему не присвоено никакого значения.

Поэтому:

```go
node == nil
```

Несмотря на это, метод:

```go
node.ValueOrZero()
```

вызвать можно.

Причина в том, что метод написан с получателем-указателем:

```go
func (n *Node) ValueOrZero() int
```

Внутри метода получатель сначала проверяется:

```go
if n == nil {
    return 0
}
```

Только после этого происходит обращение к полю:

```go
n.Value
```

Если бы без проверки на `nil` сразу было написано:

```go
return n.Value
```

из-за указателя `nil` могла бы возникнуть ошибка времени выполнения.

### 7. Method value

```go
package main

import "fmt"

type Multiplier int

func (m Multiplier) Apply(num int) int {
	return int(m) * num
}

func main() {
	two := Multiplier(2)

	apply := two.Apply

	fmt.Println(apply(7))
}
```

Здесь создано значение:

```go
two := Multiplier(2)
```

Затем через:

```go
apply := two.Apply
```

метод сохранён в переменную.

Это **method value**.

Важно, что внутри `apply` сохраняется и получатель `two`.

Поэтому при вызове:

```go
apply(7)
```

`two` снова передавать не нужно.

Go использует его в смысле:

```go
two.Apply(7)
```

Значение `two` равно `2`, а аргумент — `7`.

В результате получается:

```text
14
```

### 8. Method expression

```go
package main

import "fmt"

type Number int

func (n Number) Square() int {
	return int(n * n)
}

func main() {
	square := Number.Square

	fmt.Println(square(Number(9)))
}
```

На этот раз метод получен через:

```go
square := Number.Square
```

Это **method expression**.

В отличие от method value, здесь метод не привязан к конкретному значению получателя.

Поэтому получатель передаётся при вызове первым аргументом:

```go
square(Number(9))
```

Это почти равносильно:

```go
Number(9).Square()
```

С помощью method expression один метод можно использовать с разными значениями получателя.

Например:

```go
square(Number(5))
square(Number(10))
square(Number(20))
```

В каждом вызове первый аргумент используется как получатель.

### 9. Получатель-указатель у элементов среза

```go
package main

import "fmt"

type Product struct {
	Price int
}

func (p *Product) Discount(percent int) {
	p.Price -= p.Price * percent / 100
}

func main() {
	products := []Product{
		{Price: 100},
		{Price: 200},
	}

	for i := range products {
		products[i].Discount(10)
	}

	fmt.Println(products)
}
```

В этом примере для `Product` написан метод, изменяющий цену:

```go
func (p *Product) Discount(percent int)
```

Поскольку цена должна измениться, используется получатель-указатель.

Срез:

```go
products := []Product{
    {Price: 100},
    {Price: 200},
}
```

состоит из двух элементов.

Цикл:

```go
for i := range products {
    products[i].Discount(10)
}
```

применяет к каждому элементу скидку 10 процентов.

Важная часть здесь в том, что:

```go
products[i]
```

берётся по индексу.

Когда элемент среза берётся по индексу, его адрес можно взять.

Поэтому Go может подстроить вызов:

```go
products[i].Discount(10)
```

под получатель-указатель.

В результате значения `Price` исходных элементов среза меняются.

Первый товар дешевеет с:

```text
100
```

до:

```text
90
```

Второй товар дешевеет с:

```text
200
```

до:

```text
180
```

### 10. Последовательный выбор получателя для одного типа

```go
package main

import "fmt"

type Cart struct {
	Count int
}

func (c *Cart) Add(n int) {
	c.Count += n
}

func (c *Cart) IsEmpty() bool {
	return c.Count == 0
}

func main() {
	c := Cart{}

	fmt.Println(c.IsEmpty())

	c.Add(3)

	fmt.Println(c.IsEmpty())
}
```

В этом примере у `Cart` два метода:

```go
func (c *Cart) Add(n int)
```

и:

```go
func (c *Cart) IsEmpty() bool
```

Метод `Add()` изменяет состояние корзины:

```go
c.Count += n
```

Поэтому этому методу нужен получатель-указатель.

А `IsEmpty()` только проверяет значение:

```go
return c.Count == 0
```

Технически его можно было бы написать и с получателем-значением:

```go
func (c Cart) IsEmpty() bool {
    return c.Count == 0
}
```

Но поскольку другие методы этого типа используют получатель-указатель, `IsEmpty()` тоже написан с получателем-указателем:

```go
func (c *Cart) IsEmpty() bool
```

Так выбор получателя в методах одного типа остаётся последовательным.

В результате при работе с `Cart` меньше нужно помнить, какой метод использует указатель, а какой — получатель-значение.
