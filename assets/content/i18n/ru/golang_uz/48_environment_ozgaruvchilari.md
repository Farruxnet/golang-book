# Работа с переменными окружения

Переменная окружения (`environment variable`) — конфигурация, которую операционная система передаёт процессу программы в виде имени и значения.

Например, на каком порту работает программа, запускается ли она в режиме `development` или `production`, где находится база данных или другой внешний сервис, — всё это можно задавать через переменные окружения.

Главная польза этого — отделение конфигурации от кода.

Например, порт можно записать в коде как константу:

```go
port := "8080"
```

Но тогда для перехода в другую среду придётся менять код. Если используется переменная окружения, код не меняется. Меняется только значение в среде, где запускается программа.

Поэтому переменные окружения часто используются в серверных программах, CLI-программах, контейнерах и конфигурациях развёртывания.

## Пакет `os`

Go работает с переменными окружения через стандартный пакет `os`.

Для чтения переменной окружения в основном используются две функции:

- `os.Getenv`;
- `os.LookupEnv`.

`os.Getenv` возвращает только значение переменной.

А `os.LookupEnv` даёт две части информации:

1. значение переменной;
2. существует ли переменная вообще.

Например:

```go
package main

import (
	"fmt"
	"os"
)

func main() {
	port, ok := os.LookupEnv("APP_PORT")
	if !ok || port == "" {
		port = "8080"
	}

	fmt.Println("Порт сервера:", port)
}
```

Разберём этот код по шагам.

```go
port, ok := os.LookupEnv("APP_PORT")
```

`LookupEnv` возвращает два значения.

В `port` попадает значение `APP_PORT`.

А `ok` показывает, существует ли переменная:

```text
ok = true
```

означает, что `APP_PORT` есть в окружении.

```text
ok = false
```

означает, что такая переменная окружения вообще не задана.

Следующая проверка:

```go
if !ok || port == "" {
	port = "8080"
}
```

проверяет два случая:

- `APP_PORT` вообще не существует;
- `APP_PORT` существует, но её значение — пустая строка.

В обоих случаях программа использует значение по умолчанию `8080`.

Можно задать значение `APP_PORT` через PowerShell и затем запустить программу:

```powershell
$env:APP_PORT = "9000"
go run main.go
```

Результат:

```text
Порт сервера: 9000
```

На этот раз `LookupEnv` вернёт результат, близкий к следующему:

```text
port = "9000"
ok   = true
```

Поэтому значение по умолчанию `8080` не используется.

Если переменная не задана или её значение пустое, программа выведет:

```text
Порт сервера: 8080
```

Здесь важна разница между `LookupEnv` и `Getenv`.

Например, в окружении может быть такое значение:

```text
APP_MODE=
```

В этом случае `APP_MODE` существует, но её значение — пустая строка.

`os.Getenv("APP_MODE")` вернёт только:

```text
""
```

Но даже если переменной вообще нет, `Getenv` вернёт ровно ту же пустую строку.

Поэтому если нужно различать случаи «переменной нет» и «переменная есть, но её значение пустое», используется `os.LookupEnv`.

## Проверка значения и преобразование типа

Значения переменных окружения приходят в программу как текст, то есть в виде `string`.

Например, если записано:

```text
APP_PORT=8080
```

Go не превращает это значение автоматически в `int`.

Значение, которое получает программа, — это `string` вида:

```go
"8080"
```

Если программе нужно число, значение нужно явно преобразовать в нужный тип.

Кроме того, одного преобразования недостаточно. Нужно также проверить, что значение логически находится в допустимом диапазоне.

Например, для порта TCP или HTTP-сервера нужно число от `1` до `65535`.

```go
package main

import (
	"fmt"
	"os"
	"strconv"
)

func main() {
	raw := os.Getenv("APP_PORT")
	if raw == "" {
		raw = "8080"
	}

	port, err := strconv.Atoi(raw)
	if err != nil || port < 1 || port > 65535 {
		fmt.Fprintln(os.Stderr, "APP_PORT должен быть целым числом от 1 до 65535")
		os.Exit(1)
	}

	fmt.Printf("Сервер запускается на адресе :%d\n", port)
}
```

В этом коде сначала `APP_PORT` берётся как текст:

```go
raw := os.Getenv("APP_PORT")
```

Если значение пустое:

```go
if raw == "" {
	raw = "8080"
}
```

используется значение по умолчанию.

Пока это значение — `string`:

```text
"8080"
```

Затем через:

```go
port, err := strconv.Atoi(raw)
```

текст преобразуется в тип `int`.

Например:

```text
"8080" -> 8080
```

Если пользователь задал:

```text
APP_PORT=abc
```

`strconv.Atoi` не сможет превратить этот текст в целое число и вернёт `err`.

Поэтому проверка:

```go
if err != nil || port < 1 || port > 65535 {
```

ловит несколько недопустимых случаев.

Например:

```text
APP_PORT=abc
```

не является числом.

```text
APP_PORT=0
```

синтаксически число, но не входит в заданный нами диапазон портов.

```text
APP_PORT=70000
```

тоже целое число, но больше `65535`.

Поэтому эти значения не попадают в конфигурацию сервера.

При обнаружении ошибки:

```go
fmt.Fprintln(os.Stderr, "APP_PORT должен быть целым числом от 1 до 65535")
```

записывает сообщение в стандартный поток ошибок, то есть в `stderr`.

Затем:

```go
os.Exit(1)
```

сообщает операционной системе, что программа завершилась неудачно.

Здесь есть важное правило: переменная окружения считается данными, приходящими снаружи.

Поэтому не нужно предполагать, что её значение правильное. Перед использованием хорошей практикой считается:

- преобразовать в нужный тип;
- проверить ошибку преобразования;
- проверить допустимый диапазон.

Это правило действует и для логических значений.

Например, чтобы превратить значение:

```text
DEBUG=true
```

в `bool`, можно использовать `strconv.ParseBool`.

В реальных проектах вместо многократного чтения переменных окружения в разных частях кода удобно один раз прочитать конфигурацию при запуске программы.

Например, проверенные значения можно хранить в отдельной структуре `Config`:

```go
type Config struct {
	Port int
}
```

Тогда остальная часть программы работает не с сырыми значениями `string`, а с уже проверенной конфигурацией.

Это упрощает и обработку ошибок. Если в конфигурации есть проблема, она обнаруживается сразу в начале работы программы.

## Запись и удаление значения

Программа на Go не обязана только читать переменные окружения.

Через `os.Setenv` можно установить значение.

А `os.Unsetenv` удаляет существующую переменную.

```go
package main

import (
	"fmt"
	"os"
)

func main() {
	if err := os.Setenv("APP_MODE", "development"); err != nil {
		fmt.Fprintln(os.Stderr, err)
		os.Exit(1)
	}

	fmt.Println(os.Getenv("APP_MODE"))

	if err := os.Unsetenv("APP_MODE"); err != nil {
		fmt.Fprintln(os.Stderr, err)
		os.Exit(1)
	}
}
```

Сначала:

```go
os.Setenv("APP_MODE", "development")
```

создаёт значение `APP_MODE` в окружении текущего процесса или заменяет существующее.

После этого:

```go
os.Getenv("APP_MODE")
```

возвращает такое значение:

```text
development
```

Затем:

```go
os.Unsetenv("APP_MODE")
```

удаляет `APP_MODE` из окружения текущего процесса.

`Setenv` и `Unsetenv` могут вернуть ошибку. Поэтому в примере проверяется `err`.

Об этих функциях есть важный момент.

Они не меняют постоянную конфигурацию терминала или операционной системы.

Например, вызов внутри программы:

```go
os.Setenv("APP_MODE", "development")
```

не меняет постоянную настройку в PowerShell или другом окне терминала.

Значение существует в основном в окружении текущего процесса.

Если эта программа на Go позже запустит другой дочерний процесс (child process), он обычно тоже может унаследовать значение на основе текущего окружения.

Значит, `os.Setenv` — не инструмент для редактирования глобальной и постоянной настройки окружения операционной системы.

## Что такое файл `.env`?

`.env` — широко используемый обычный текстовый файл для записи конфигурации окружения в виде `KEY=value`.

Например:

```text
APP_PORT=8080
APP_MODE=development
```

В этом файле:

```text
APP_PORT
```

и:

```text
APP_MODE
```

— имена ключей.

А значения справа от них — значения конфигурации.

Важно то, что `.env` — не специальный формат файла языка Go.

Это также не универсальный автоматический формат окружения операционной системы.

Это просто распространённое соглашение.

Стандартная библиотека Go не видит файл `.env` и не делает автоматически значение:

```text
APP_PORT=8080
```

доступным через `os.Getenv("APP_PORT")`.

Значения нужно загрузить в окружение программы другим способом.

Например:

- экспортировать в окружение средствами shell;
- прочитать файл `.env` с помощью специального внешнего пакета.

Поэтому одного наличия в проекте такого файла недостаточно:

```text
APP_PORT=8080
APP_MODE=development
```

Если он не загружен в окружение:

```go
os.Getenv("APP_PORT")
```

не увидит это значение.

**Внимание**

Не коммитьте в репозиторий секретные значения, такие как пароли, токены и API-ключи.

Если `.env` используется для локальной разработки, обычная практика — добавить его в файл `.gitignore`.

При этом полезно документировать, какие имена переменных окружения ожидает проект. Для этого можно создать файл `.env.example` без секретных значений.

Например:

```text
APP_PORT=8080
APP_MODE=development
API_TOKEN=
```

Этот файл показывает нужные имена переменных, но не хранит настоящие секретные значения.

В production-среде вместо хранения секретных данных в обычном файле `.env` предпочтительнее использовать менеджер секретов (`secret manager`).

## Частые ошибки

Хотя работа с переменными окружения кажется простой, есть несколько тонких случаев.

- Всегда считать пустую строку, возвращённую `os.Getenv`, признаком того, что «переменной нет».

  `os.Getenv` может вернуть `""` и когда переменной вообще нет, и когда она есть, но значение пустое.

  Если разница между этими двумя случаями важна, используйте `os.LookupEnv`:

  ```go
  value, ok := os.LookupEnv("APP_MODE")
  ```

  Здесь `ok` отдельно показывает, существует ли переменная.

- Использовать числовые и логические значения без проверки.

  Все значения в окружении приходят как текст.

  Например:

  ```text
  APP_PORT=abc
  ```

  с точки зрения окружения тоже обычное текстовое значение.

  Если вы хотите использовать его как число, нужно проверять ошибку `strconv.Atoi`.

  Точно так же для значения `bool` нельзя игнорировать ошибку, возвращённую `strconv.ParseBool`.

- Выводить секретное значение в лог.

  Например, если `API_TOKEN` в конфигурации неверен, записывать сам токен в сообщение об ошибке опасно:

  ```text
  invalid API_TOKEN: abc123-secret-token
  ```

  Вместо этого обычно достаточно указать имя переменной:

  ```text
  неверная конфигурация API_TOKEN
  ```

  Логи часто отправляются в отдельные системы мониторинга. Поэтому вывод секретных данных в лог может привести к их распространению.

- Думать, что если внешнее значение окружения изменится во время работы программы, конфигурация программы обновится автоматически.

  Процесс обычно запускается со своим окружением.

  Например, если позже написать в shell:

  ```powershell
  $env:APP_PORT = "9001"
  ```

  это не изменит автоматически окружение другого, уже работающего процесса.

  Поэтому многие программы читают конфигурацию один раз при запуске и затем хранят проверенные значения в памяти.

  Если программе нужно обновлять конфигурацию во время работы, для этого нужен отдельный механизм. Например, повторное чтение конфигурационного файла, приём сигнала или использование внешнего сервиса конфигурации.
