# Работа с каталогами в Go

Каталог — объект файловой системы, который группирует и хранит файлы и другие каталоги. В программах на Go каталоги часто используются, чтобы упорядоченно хранить конфигурационные файлы, логи, кеш, загруженные пользователями файлы и временные данные.

Но работа с каталогами — это не только создание новой папки. Реальная программа должна учитывать несколько важных ситуаций:

* пути к файлам в Linux, macOS и Windows выглядят по-разному;
* права каталогов и файлов различаются в зависимости от операционной системы;
* символическая ссылка ведёт себя иначе, чем обычный каталог или файл;
* путь, пришедший снаружи, может быть опасным;
* если рекурсивное удаление вызвать с неправильным путём, можно потерять много данных.

В стандартной библиотеке Go для работы с каталогами в основном используются пакеты `os` и `path/filepath`.

Пакет `os` выполняет операции файловой системы: создание, чтение, удаление и переименование каталогов. А `path/filepath` помогает строить и разбирать пути к файлам с учётом локальной операционной системы.

## Как устроен путь к файлу?

Путь к файлу (**path**) обозначает адрес файла или каталога в файловой системе.

Путь бывает двух видов:

* **абсолютный путь — absolute path**;
* **относительный путь — relative path**.

Абсолютный путь обозначает точное место в файловой системе.

В системах семейства Unix он обычно начинается с корня `/`:

```text
/home/user/project/data.json
```

В Windows он может начинаться, например, с буквы диска:

```text
C:\Users\user\project\data.json
```

А относительный путь вычисляется относительно текущего рабочего каталога:

```text
data/reports/daily.json
```

Здесь есть важное различие. **Текущий рабочий каталог — это не каталог, в котором лежит исполняемый файл.**

Например, исполняемый файл может находиться в `/usr/local/bin/app`. Но если запустить его из каталога `/home/user/project`, относительные пути обычно вычисляются относительно `/home/user/project`.

Текущий рабочий каталог можно получить через `os.Getwd()`.

Объединять части пути вручную разделителями `"/"` или `"\\"` не рекомендуется. Вместо этого используется `filepath.Join`. Он выбирает разделитель, подходящий текущей операционной системе, и убирает лишние разделители.

```go
package main

import (
	"fmt"
	"os"
	"path/filepath"
)

func main() {
	path := filepath.Join("data", "reports", "daily.json")
	absPath, err := filepath.Abs(path)
	if err != nil {
		fmt.Println("получение абсолютного пути:", err)
		return
	}

	fmt.Println("имя файла:", filepath.Base(path))
	fmt.Println("каталог:", filepath.Dir(path))
	fmt.Println("расширение:", filepath.Ext(path))
	fmt.Println("абсолютный путь:", absPath)
	fmt.Println("абсолютный:", filepath.IsAbs(absPath))
	fmt.Println("разделитель:", string(os.PathSeparator))
}
```

Теперь рассмотрим функции в коде по отдельности.

```go
path := filepath.Join("data", "reports", "daily.json")
```

`filepath.Join` объединяет заданные части пути в виде, подходящем операционной системе.

В системе Unix результат примерно такой:

```text
data/reports/daily.json
```

А в Windows может быть таким:

```text
data\reports\daily.json
```

Следующая строка:

```go
absPath, err := filepath.Abs(path)
```

превращает относительный путь в абсолютный.

Например, если программа запущена внутри `/home/farrux/project`:

```text
data/reports/daily.json
```

может превратиться в абсолютный путь вроде:

```text
/home/farrux/project/data/reports/daily.json
```

`filepath.Base(path)` возвращает последнюю часть пути:

```text
daily.json
```

`filepath.Dir(path)` возвращает его родительский каталог:

```text
data/reports
```

`filepath.Ext(path)` возвращает последнее расширение файла:

```text
.json
```

`filepath.IsAbs(absPath)` проверяет, абсолютный путь или относительный.

А `os.PathSeparator` даёт разделитель каталогов, используемый текущей операционной системой.

Точные значения абсолютного пути и разделителя зависят от того, в какой операционной системе и из какого каталога вы запускаете программу. Поэтому полный вывод этого примера не одинаков на всех платформах.

> **Информация**
>
> `path/filepath` используется для путей локальной файловой системы.
>
> У путей внутри URL другие правила. В путях URL разделитель всегда `/`. Для них нужно использовать пакет `path` или `net/url`.
>
> Например, воспринимать путь к файлу Windows как URL или собирать путь URL через `filepath.Join` может привести к неправильному результату.

## Создание одного каталога

Для создания одного каталога используется `os.Mkdir`.

Важное правило: `os.Mkdir` создаёт только сам указанный каталог. Его родительский каталог должен уже существовать.

Например:

```go
package main

import (
	"errors"
	"fmt"
	"os"
)

func main() {
	err := os.Mkdir("mydir", 0o755)
	switch {
	case err == nil:
		fmt.Println("каталог создан")
	case errors.Is(err, os.ErrExist):
		fmt.Println("каталог уже существует")
	default:
		fmt.Println("каталог не создан:", err)
	}
}
```

Этот код пытается создать новый каталог с именем `mydir` внутри текущего рабочего каталога.

```go
os.Mkdir("mydir", 0o755)
```

Здесь:

* `"mydir"` — путь создаваемого каталога;
* `0o755` — биты прав.

`0o755` — значение прав, записанное в восьмеричной системе счисления.

В системах семейства Unix оно обычно интерпретируется так:

```text
владелец:  rwx
группа:    r-x
остальные: r-x
```

Для каталога `x`, то есть бит выполнения, не означает запуск файла.

Бит `x` у каталога позволяет обращаться к именам внутри него. Например, право `x` нужно, чтобы получить доступ к файлу внутри каталога или перейти во вложенный каталог.

А бит `r` помогает читать список имён внутри каталога.

Поэтому понимать права каталогов точно в том же смысле, что и права файлов, неправильно.

Ещё один важный момент: `0o755` не всегда гарантирует создание каталога ровно с правами `755`. В системах Unix на итоговые права может влиять значение `umask` процесса.

Модель прав в Windows отличается от Unix. Поэтому биты прав Unix там могут работать не в том же смысле.

Проверка в коде:

```go
errors.Is(err, os.ErrExist)
```

определяет, что путь уже существует.

Но из этой проверки нельзя сделать вывод:

> «значит, по этому пути есть каталог»

Например, даже если существует обычный файл с именем `mydir`, `os.Mkdir` вернёт ошибку, и она может соответствовать `os.ErrExist`.

Если важно, чтобы существующий объект был именно каталогом, это нужно отдельно проверить через `os.Stat` и `IsDir()`.

## Создание вложенных каталогов

Для создания нескольких вложенных каталогов удобнее `os.MkdirAll`.

Например, мы хотим создать такой путь:

```text
cache/images/thumbnails
```

Если `cache` и `images` ещё не существуют, с обычным `os.Mkdir` придётся создавать каждый уровень отдельно.

`os.MkdirAll` сам создаёт и недостающие родительские каталоги.

```go
package main

import (
	"fmt"
	"os"
	"path/filepath"
)

func main() {
	dir := filepath.Join(os.TempDir(), "go-dirs-lesson", "cache", "images")
	if err := os.MkdirAll(dir, 0o755); err != nil {
		fmt.Println("создание каталогов:", err)
		return
	}
	defer os.RemoveAll(filepath.Join(os.TempDir(), "go-dirs-lesson"))

	fmt.Println("последний каталог:", filepath.Base(dir))
}
```

Результат:

```text
последний каталог: images
```

Сначала:

```go
os.TempDir()
```

даёт стандартный временный каталог операционной системы.

Затем:

```go
filepath.Join(
	os.TempDir(),
	"go-dirs-lesson",
	"cache",
	"images",
)
```

объединяет части пути.

В результате может получиться путь примерно такой:

```text
/tmp/go-dirs-lesson/cache/images
```

В Windows может использоваться другой временный каталог.

Следующая строка:

```go
os.MkdirAll(dir, 0o755)
```

создаёт все несуществующие каталоги пути.

Например, если каталогов:

```text
go-dirs-lesson
go-dirs-lesson/cache
go-dirs-lesson/cache/images
```

нет, создаются все три.

У `MkdirAll` есть ещё одно удобное свойство: если каталоги уже существуют, он не возвращает ошибку только по этой причине.

Поэтому многократный вызов такого кода обычно не создаёт проблем:

```go
os.MkdirAll(dir, 0o755)
```

Когда повторное выполнение той же операции не портит результат, такое свойство называется **идемпотентностью**.

Строка в примере:

```go
defer os.RemoveAll(filepath.Join(os.TempDir(), "go-dirs-lesson"))
```

удаляет дерево каталогов, созданное для примера, при завершении программы.

Это удобно в тесте или учебном примере.

Но в реальной программе для постоянных данных такой код нельзя использовать вслепую. `os.RemoveAll` может удалить целое дерево каталогов.

## Чтение содержимого каталога

Для получения списка файлов и вложенных каталогов внутри каталога используется `os.ReadDir`.

`os.ReadDir` возвращает только записи, находящиеся **непосредственно внутри** указанного каталога. Он не заходит автоматически во вложенные каталоги.

Например:

```text
root/
├── config.json
└── images/
    └── logo.png
```

Если вызвать `os.ReadDir(root)`, вернутся:

```text
config.json
images
```

Но `images/logo.png` автоматически не вернётся.

```go
package main

import (
	"fmt"
	"os"
	"path/filepath"
)

func main() {
	root, err := os.MkdirTemp("", "read-dir-*")
	if err != nil {
		fmt.Println("создание временного каталога:", err)
		return
	}
	defer os.RemoveAll(root)

	if err := os.Mkdir(filepath.Join(root, "images"), 0o755); err != nil {
		fmt.Println("создание вложенного каталога:", err)
		return
	}
	if err := os.WriteFile(filepath.Join(root, "config.json"), []byte("{}\n"), 0o644); err != nil {
		fmt.Println("создание файла:", err)
		return
	}

	entries, err := os.ReadDir(root)
	if err != nil {
		fmt.Println("чтение каталога:", err)
		return
	}

	for _, entry := range entries {
		kind := "FILE"
		if entry.IsDir() {
			kind = "DIR"
		}
		fmt.Printf("[%s] %s\n", kind, entry.Name())
	}
}
```

Результат:

```text
[FILE] config.json
[DIR] images
```

Первая часть:

```go
root, err := os.MkdirTemp("", "read-dir-*")
```

создаёт временный каталог.

Затем внутри него создаются каталог:

```go
images
```

и файл:

```text
config.json
```

После этого:

```go
entries, err := os.ReadDir(root)
```

читает записи внутри каталога.

`os.ReadDir` возвращает результат, отсортированный по имени.

Каждый элемент — значение `os.DirEntry`.

Через `DirEntry`, например:

```go
entry.Name()
```

можно получить имя записи.

```go
entry.IsDir()
```

определяет, каталог это или нет.

`os.DirEntry` намеренно даёт относительно лёгкую информацию. Если нужны размер файла, время изменения или другие полные метаданные, можно вызвать:

```go
info, err := entry.Info()
```

Но `Info()` может выполнить дополнительную операцию с файловой системой и может вернуть ошибку. Поэтому полезно вызывать его только при необходимости.

Есть ещё один важный момент.

`os.ReadDir` загружает все записи каталога в память в виде slice.

Для обычных каталогов это не проблема. Но если в каталоге миллионы записей, загрузка их всех в память сразу может дорого обойтись.

В таком случае каталог можно открыть через:

```go
file, err := os.Open(path)
```

а затем читать частями через:

```go
file.ReadDir(n)
```

Например, чтение по 1000 записей за раз помогает ограничить расход памяти.

Когда каталог открывается через `os.Open`, возвращается `*os.File`. После использования его нужно закрыть:

```go
defer file.Close()
```

## Обход дерева каталогов

Иногда нужно увидеть не один уровень каталога, а все каталоги и файлы внутри него.

Для этого используется `filepath.WalkDir`.

Например, пусть есть такое дерево:

```text
root/
└── docs/
    └── readme.txt
```

`WalkDir` может обойти пути:

1. `root`;
2. `root/docs`;
3. `root/docs/readme.txt`.

```go
package main

import (
	"fmt"
	"io/fs"
	"os"
	"path/filepath"
)

func main() {
	root, err := os.MkdirTemp("", "walk-dir-*")
	if err != nil {
		fmt.Println("создание временного каталога:", err)
		return
	}
	defer os.RemoveAll(root)

	docs := filepath.Join(root, "docs")
	if err := os.Mkdir(docs, 0o755); err != nil {
		fmt.Println("создание каталога:", err)
		return
	}
	if err := os.WriteFile(filepath.Join(docs, "readme.txt"), []byte("Привет\n"), 0o644); err != nil {
		fmt.Println("создание файла:", err)
		return
	}

	err = filepath.WalkDir(root, func(path string, entry fs.DirEntry, walkErr error) error {
		if walkErr != nil {
			return walkErr
		}

		rel, err := filepath.Rel(root, path)
		if err != nil {
			return err
		}
		kind := "FILE"
		if entry.IsDir() {
			kind = "DIR"
		}
		fmt.Printf("[%s] %s\n", kind, rel)
		return nil
	})
	if err != nil {
		fmt.Println("обход каталога:", err)
	}
}
```

В системе Unix результат выглядит примерно так:

```text
[DIR] .
[DIR] docs
[FILE] docs/readme.txt
```

В Windows последний путь может выглядеть так:

```text
docs\readme.txt
```

В `WalkDir` передаётся callback-функция:

```go
func(path string, entry fs.DirEntry, walkErr error) error
```

Этот callback вызывается для каждой найденной записи.

`path` — путь текущей записи.

`entry` — `fs.DirEntry` о текущем файле или каталоге.

`walkErr` обозначает ошибку, возникшую при посещении именно этого пути.

Здесь важно первым делом проверить `walkErr`:

```go
if walkErr != nil {
	return walkErr
}
```

Причина в том, что при ошибке использовать `entry` может быть небезопасно. Вызов методов `entry` без проверки в некоторых ситуациях может вызвать panic.

Затем:

```go
rel, err := filepath.Rel(root, path)
```

получает более короткий путь относительно `root` вместо абсолютного или длинного временного пути.

Например, вместо:

```text
/tmp/walk-dir-123456/docs/readme.txt
```

выводится:

```text
docs/readme.txt
```

`filepath.WalkDir` обычно может быть эффективнее старого `filepath.Walk`. Причина в том, что в callback передаётся не `os.FileInfo`, а `os.DirEntry`. Благодаря этому для некоторых файлов может не понадобиться дополнительный вызов `os.Lstat`.

### Пропуск каталога

Иногда при обходе дерева вы вообще не хотите заходить в некоторые каталоги.

Например, может понадобиться пропустить каталоги вроде:

```text
.git
node_modules
cache
```

Если callback каталога вернёт:

```go
return filepath.SkipDir
```

`WalkDir` не зайдёт внутрь этого каталога.

Чтобы пропустить один обычный файл, обычно никакой специальный сигнал не нужен. Callback возвращает `nil`, и обход переходит к следующей записи.

`fs.SkipAll` имеет другой смысл: он используется для остановки всего обхода. Поэтому использовать `fs.SkipAll` для пропуска одного файла неправильно.

Ещё один тонкий случай: `WalkDir` обычно не следует автоматически по символической ссылке в каталог, на который она указывает.

Например, если:

```text
root/link -> /other/data
```

`link` может появиться как запись. Но всё дерево внутри `/other/data` автоматически не обходится.

Такое поведение снижает риск неожиданного цикла или выхода в другое дерево каталогов из-за символической ссылки.

## Относительные и абсолютные пути

В пакете `path/filepath` есть несколько важных функций для вычисления путей.

`filepath.Abs` приводит относительный путь к абсолютному виду относительно текущего рабочего каталога.

Например, для:

```text
data/config.json
```

если текущий рабочий каталог:

```text
/home/user/app
```

результат может быть примерно таким:

```text
/home/user/app/data/config.json
```

`filepath.Rel(base, target)` вычисляет, каким относительным путём дойти от `base` до `target`.

Например, для:

```text
base:   /home/user/app
target: /home/user/app/data/config.json
```

результат может быть:

```text
data/config.json
```

Важный момент: `filepath.Abs` и `filepath.Rel` в основном вычисляют путь **логически**. Сами по себе они не проверяют, существует ли файл или каталог в реальной файловой системе.

### `filepath.Clean`

`filepath.Clean` нормализует синтаксис пути.

Например:

```text
data/./reports/../config.json
```

может упроститься до:

```text
data/config.json
```

Он:

* убирает части `.`;
* по возможности вычисляет части `..`;
* убирает лишние разделители.

Но здесь есть очень важное правило безопасности:

> `filepath.Clean` — не проверка безопасности.

Например:

```go
filepath.Clean("uploads/../../config")
```

нормализует путь, но не запрещает ему выходить за пределы каталога `uploads`.

Значит, `Clean` выполняет задачу:

> «привести синтаксис пути в порядок»

Он не выполняет политику безопасности:

> «пользователь должен оставаться только внутри этого каталога»

### Проверка пути внутри базового каталога

Имя файла, пришедшее по HTTP, параметр URL или аргумент CLI могут быть недоверенными.

Например, пользователь может прислать путь:

```text
../../config.json
```

Если программа вслепую объединит его через:

```go
filepath.Join("uploads", name)
```

и затем откроет файл, пользователь может попытаться выйти к файлам за пределами разрешённого каталога `uploads`.

Это приводит к уязвимости, называемой **path traversal**.

В следующем примере мы проверяем, что путь остаётся внутри базового каталога:

```go
package main

import (
	"fmt"
	"path/filepath"
	"strings"
)

func safeJoin(base, name string) (string, error) {
	if filepath.IsAbs(name) {
		return "", fmt.Errorf("абсолютные пути не разрешены")
	}

	baseAbs, err := filepath.Abs(base)
	if err != nil {
		return "", fmt.Errorf("базовый путь: %w", err)
	}
	target := filepath.Join(baseAbs, name)
	rel, err := filepath.Rel(baseAbs, target)
	if err != nil {
		return "", fmt.Errorf("относительный путь: %w", err)
	}
	if rel == ".." || strings.HasPrefix(rel, ".."+string(filepath.Separator)) {
		return "", fmt.Errorf("путь вышел за пределы базового каталога")
	}
	return target, nil
}

func main() {
	for _, name := range []string{"images/logo.png", "../../config.json"} {
		path, err := safeJoin("uploads", name)
		if err != nil {
			fmt.Printf("%s: отклонено\n", name)
			continue
		}
		fmt.Printf("%s: разрешено (%s)\n", name, filepath.Base(path))
	}
}
```

Результат:

```text
images/logo.png: разрешено (logo.png)
../../config.json: отклонено
```

Теперь разберём проверку по шагам.

Сначала:

```go
if filepath.IsAbs(name) {
	return "", fmt.Errorf("абсолютные пути не разрешены")
}
```

проверяет, что пользователь не прислал абсолютный путь напрямую.

Например, путь вроде:

```text
/etc/passwd
```

может быть сразу отклонён.

Затем:

```go
baseAbs, err := filepath.Abs(base)
```

получает абсолютный путь базового каталога.

Например:

```text
uploads
```

может превратиться в:

```text
/home/app/uploads
```

Затем:

```go
target := filepath.Join(baseAbs, name)
```

объединяет присланное пользователем имя с базовым путём.

Затем:

```go
rel, err := filepath.Rel(baseAbs, target)
```

вычисляет относительный путь от `baseAbs` до `target`.

В обычном случае получается:

```text
images/logo.png
```

Но для пути, выходящего наружу, может получиться:

```text
../../config.json
```

или похожее значение, начинающееся с `..`.

Поэтому проверка:

```go
if rel == ".." || strings.HasPrefix(rel, ".."+string(filepath.Separator))
```

определяет, что путь поднимается в родительский каталог.

Здесь простой проверки:

```go
strings.HasPrefix(target, base)
```

недостаточно.

Например, если:

```text
base   = /data/app
target = /data/app-old/file.txt
```

`target` как строка начинается с `/data/app`.

Но `/data/app-old` не находится внутри каталога `/data/app`.

Значит, в путях файловой системы простой строковый префикс неправильно выражает границу каталога.

> **Внимание**
>
> `safeJoin` выше выполняет лексическую проверку, то есть основанную на тексте пути. Она не полностью предотвращает выход за пределы базового каталога через символическую ссылку.
>
> Например, если пользователь может создать внутри `uploads` символическую ссылку, указывающую на внешний каталог, путь как текст всё ещё может выглядеть так, будто он внутри `uploads`.
>
> Если такой риск есть, может понадобиться проверять символические ссылки через `os.Lstat`, определять реальный путь через `filepath.EvalSymlinks` или использовать более безопасные API операционной системы, работающие относительно дескриптора каталога.
>
> Ещё одна проблема — время между проверкой и реальным открытием файла. Если внешний процесс за это время изменит файловую систему, может возникнуть состояние гонки. Это может привести к проблемам типа **TOCTOU**, то есть «time-of-check to time-of-use».

## Переименование и перемещение каталога

Для переименования файла или каталога используется:

```go
os.Rename(oldPath, newPath)
```

Например:

```go
err := os.Rename("reports", "archive")
```

пытается переименовать каталог `reports` в `archive`.

`os.Rename` используется не только для переименования, но в некоторых случаях и для перемещения объекта в другой каталог.

Например:

```go
os.Rename(
	"uploads/file.txt",
	"archive/file.txt",
)
```

может переместить файл в другой каталог в пределах одной файловой системы.

`Rename` в пределах одной файловой системы обычно работает быстро. Причина в том, что часто не нужно заново копировать всё содержимое файла или каталога. Меняются метаданные в файловой системе.

Но между разными дисками или разными точками монтирования ситуация другая.

Например, при перемещении из:

```text
/mnt/disk1/data
```

в:

```text
/mnt/disk2/data
```

`os.Rename` может вернуть ошибку.

В таком случае обычно нужен такой процесс:

1. скопировать содержимое источника в новое место;
2. сохранить нужные права и другие метаданные;
3. проверить, что копирование полностью успешно;
4. только после этого удалить старую копию.

Это гораздо сложнее простого `Rename`.

Ещё один важный момент: что произойдёт, если `newPath` уже существует, может зависеть от операционной системы и типа объекта.

В Linux и Windows правила замены, особенно открытых файлов, не одинаковы.

Поэтому при написании кроссплатформенной программы важные сценарии с `Rename` нужно проверять не только в одной операционной системе, а на всех поддерживаемых платформах.

## Удаление каталога

Для удаления пустого каталога можно использовать `os.Remove`.

Например:

```go
err := os.Remove("empty-dir")
```

Если внутри каталога есть файлы или другие каталоги, `os.Remove` обычно возвращает ошибку.

Для рекурсивного удаления всего дерева каталогов используется `os.RemoveAll`:

```go
if err := os.RemoveAll(cacheDir); err != nil {
	return fmt.Errorf("удаление каталога кеша: %w", err)
}
```

Этот фрагмент — не самостоятельная полная программа.

Он должен быть написан внутри функции, возвращающей `error`. Кроме того, поскольку используется `fmt.Errorf`, нужно импортировать пакет `fmt`.

`os.RemoveAll(cacheDir)` может полностью удалить дерево вроде:

```text
cache/
├── images/
│   ├── a.jpg
│   └── b.jpg
└── metadata.json
```

То есть удаляется не только каталог `cache`, но и все файлы и каталоги внутри него.

**Внимание**

`os.RemoveAll` — очень мощная операция.

Если вызвать её с неправильным путём, она может безвозвратно удалить большой объём данных.

Особенно опасными могут быть такие значения:

```text
.
```

или неправильно вычисленный широкий путь каталога.

Перед `RemoveAll` нужно точно проверить, что путь — именно каталог, которым управляет программа.

Не передавайте путь, присланный пользователем по HTTP, через CLI или из другого внешнего источника, напрямую в `os.RemoveAll` без всякой проверки.

Если `os.RemoveAll` вызвать для несуществующего пути, он обычно возвращает `nil`.

Это делает его удобным в процессах очистки. Например, даже если каталог был удалён раньше, ошибка только по этой причине снова не возникнет.

С символическими ссылками тоже есть важное поведение.

Если путь указывает на саму символическую ссылку, `RemoveAll` обычно удаляет ссылку. Он не заходит автоматически во внешнее дерево каталогов, на которое указывает ссылка, и не удаляет его рекурсивно.

Но это не устраняет все риски.

Если внешние процессы могут изменить файловую систему между вашей проверкой и операцией удаления, простой проверки пути может быть недостаточно.

В программах, чувствительных к безопасности, такие состояния гонки нужно учитывать отдельно.

## Временные каталоги

Некоторые каталоги нужны лишь ненадолго.

Например:

* во время теста;
* при конвертации файла;
* при временной распаковке архива;
* при разбиении большого файла на части;
* при хранении временных промежуточных результатов.

В таких ситуациях можно использовать `os.MkdirTemp`.

```go
dir, err := os.MkdirTemp("", "report-*")
if err != nil {
	return err
}
defer os.RemoveAll(dir)
```

Если первый аргумент:

```go
""
```

— пустая строка, используется стандартный временный каталог операционной системы.

Второй аргумент:

```text
report-*
```

— шаблон имени каталога.

Часть `*` заменяется случайным значением.

В результате может быть создан каталог примерно такой:

```text
/tmp/report-184729153
```

Важный момент: `MkdirTemp` не просто предлагает уникальное имя. Он **сам создаёт каталог** и затем возвращает путь.

Это важно с точки зрения безопасности.

Неправильный подход мог бы выглядеть так:

1. найти случайное имя;
2. проверить, что это имя свободно;
3. затем создать каталог.

Между шагом 2 и шагом 3 другой процесс мог бы занять это имя.

`MkdirTemp` помогает предотвратить такое состояние гонки «проверь, потом создай».

Строка в примере:

```go
defer os.RemoveAll(dir)
```

очищает временный каталог при завершении функции.

В коротких функциях или тестах это очень удобно.

Но в долго работающем сервере нельзя забывать, когда срабатывает `defer`.

Если `defer` написан в очень долгоживущей функции вроде `main`, временный каталог может не удаляться, пока сервер работает часами или днями.

Поэтому в реальном сервере нужно заранее определить:

* сколько живёт временный каталог;
* когда он очищается;
* что будет, если программа упадёт;
* кто и когда удаляет старые каталоги.

## Частые ошибки

### Объединение путей через строки

Строить путь так не рекомендуется:

```go
path := base + "/" + name
```

На первый взгляд это кажется простым и рабочим решением.

Но есть несколько проблем:

* Windows может использовать другой разделитель;
* если `base` заканчивается разделителем, может появиться два разделителя;
* `name` может прийти в неожиданном виде;
* вопросы нормализации пути не учитываются.

Для путей локальной файловой системы лучше использовать:

```go
filepath.Join(base, name)
```

Но `filepath.Join` сам по себе не делает внешний путь безопасным. Если есть риск path traversal, границу базового каталога нужно проверять отдельно.

### Считать `Mkdir` и `MkdirAll` одинаковыми

Хотя эти две функции похожи, их задачи разные.

`Mkdir`:

```go
os.Mkdir(path, perm)
```

создаёт только последний каталог.

Например, для:

```text
data/cache/images
```

если `data/cache` не существует, обычный `Mkdir` завершится неудачей.

А `MkdirAll`:

```go
os.MkdirAll(path, perm)
```

создаёт и недостающие родительские каталоги.

Ещё одно отличие: если нужное дерево каталогов уже существует, `MkdirAll` не возвращает ошибку только по этой причине.

### Думать, что `os.ReadDir` читает и вложенное дерево

`os.ReadDir` возвращает только один уровень каталога.

Например, для:

```text
root/
├── a.txt
└── sub/
    └── b.txt
```

в результате:

```go
os.ReadDir(root)
```

получается:

```text
a.txt
sub
```

`sub/b.txt` автоматически не возвращается.

Если нужно рекурсивно просмотреть всё дерево каталогов, используется:

```go
filepath.WalkDir(...)
```

### Считать `filepath.Clean` средством безопасности

`filepath.Clean` синтаксически нормализует путь.

Например, он может привести:

```text
a/./b/../c
```

к виду:

```text
a/c
```

Но он не отвечает на вопрос:

> «находится ли этот путь внутри каталога, разрешённого пользователю?»

Поэтому:

* нормализация пути;
* проверка границы разрешённого каталога;
* учёт символических ссылок

— это отдельные задачи.

### Неправильное понимание бита выполнения в правах каталога

В системе Unix бит `x` для каталога имеет другой смысл, чем бит `x` у обычного исполняемого файла.

У каталога бит `x` позволяет обращаться к записям внутри него.

Например, если вы знаете, что внутри каталога есть `file.txt`, для доступа к нему может понадобиться право `x` на каталог.

А бит `r` связан с получением списка имён внутри каталога.

Поэтому если у каталога есть:

```text
r
```

но нет:

```text
x
```

даже если имена внутри каталога видны, их использование может быть ограничено.

При работе с правами не смешивайте смысл битов `r`, `w` и `x` у каталога с их смыслом у файла.

## На что обращают внимание на собеседовании?

Когда спрашивают о каталогах и путях к файлам в Go, знания только имён функций может быть недостаточно. Важно уметь объяснить их задачу и ограничения.

* Пакет `path` используется для общих путей со слешем `/` в качестве разделителя, например URL. А `path/filepath` предназначен для путей к файлам локальной операционной системы.

* `os.Mkdir` создаёт один каталог и требует существования родительского каталога. `os.MkdirAll` создаёт и недостающие каталоги пути.

* `MkdirAll` не возвращает ошибку только потому, что дерево каталогов уже существует. Поэтому его удобно использовать идемпотентно.

* `os.ReadDir` читает только один уровень каталога. Во вложенные каталоги он автоматически не заходит.

* Для рекурсивного обхода используется `filepath.WalkDir`.

* `WalkDir` обычно не следует автоматически по символической ссылке в каталог. Сама символическая ссылка отображается как запись.

* `filepath.Clean` нормализует синтаксис пути. Но он не проверяет границу безопасности.

* Чтобы предотвратить path traversal, отдельно проверяется, что путь, заданный пользователем, не выходит за пределы базового каталога.

* Простой проверки `strings.HasPrefix(target, base)` недостаточно для определения границы каталога.

* Если есть символические ссылки, проверка пути только по тексту не закрывает все риски.

* `os.Remove` может удалить пустой каталог. `os.RemoveAll` рекурсивно удаляет всё дерево каталогов.

* `os.RemoveAll` — мощная и опасная операция. Её аргумент нужно проверять на границе доверия.

* `os.MkdirTemp` создаёт уникальный временный каталог более безопасным способом. Он уменьшает состояние гонки при предварительной проверке имени каталога и последующем создании.

* `os.Rename` в пределах одной файловой системы обычно работает быстро. Но между разными дисками или точками монтирования может вернуть ошибку.

В следующем уроке мы научимся использовать пакет `embed`, чтобы добавлять файлы в Go-программу на этапе компиляции.
