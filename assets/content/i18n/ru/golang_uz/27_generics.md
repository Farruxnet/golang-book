# Работа с generics в Go

Generics (обобщённое программирование) позволяют использовать один и тот же алгоритм с несколькими типами. При этом не нужно писать отдельную функцию для каждого типа.

Например, можно написать одну функцию для суммирования значений `int` и другую — для суммирования значений `float64`. Но если обе функции работают одинаково, это приводит к дублированию кода.

С помощью generics сам тип можно передать как параметр. Такой параметр называется **параметром типа** (type parameter).

В результате одна функция может работать с:

* `int`;
* `int64`;
* `float64`;
* или другими типами, которые разрешает ограничение (constraint).

Важно, что при этом информация о типе не теряется. Компилятор знает, какой тип используется, и может обнаружить значения неверного типа на этапе компиляции.

Go поддерживает generics начиная с версии 1.18.

Тем не менее не каждую функцию нужно делать обобщённой. Generics особенно полезны, когда:

* алгоритм одинаковый;
* различаются только используемые типы;
* они сокращают дублирование кода;
* нужно сохранить связь между входными и выходными типами.

Если обобщённый код становится сложнее и труднее для чтения, чем обычный, использовать его не обязательно.

## Зачем нужны generics?

Представьте, что в программе мы работаем с заказами.

Количество товаров в заказе хранится как `int`:

```go
[]int
```

А цены могут быть `float64`:

```go
[]float64
```

Нужно просуммировать значения в обоих slice.

Без generics можно написать две отдельные функции:

```go
func sumInts(values []int) int {
	var total int
	for _, value := range values {
		total += value
	}
	return total
}

func sumFloats(values []float64) float64 {
	var total float64
	for _, value := range values {
		total += value
	}
	return total
}
```

Этот код работает.

Первая функция:

```go
func sumInts(values []int) int
```

принимает только `[]int` и возвращает `int`.

Вторая функция:

```go
func sumFloats(values []float64) float64
```

принимает `[]float64` и возвращает `float64`.

Но если заглянуть внутрь функций, алгоритм почти полностью одинаковый:

```go
var total ...
for _, value := range values {
	total += value
}
return total
```

Изменились только имена типов.

Если теперь понадобится работать и с `int64`, придётся писать третью функцию. Потом, если добавится другой числовой тип, появится ещё одна копия.

Здесь generics полезны.

Разницу в типах можно выразить не копиями кода, а параметром типа:

```go
package main

import "fmt"

type Number interface {
	~int | ~int64 | ~float64
}

func sum[T Number](values []T) T {
	var total T
	for _, value := range values {
		total += value
	}
	return total
}

func main() {
	quantities := []int{2, 3, 5}
	prices := []float64{12.5, 7.25, 10}

	fmt.Println(sum(quantities))
	fmt.Println(sum(prices))
}
```

Результат:

```text
10
29.75
```

Здесь одна функция `sum()` поработала с двумя разными типами.

Для первого вызова:

```go
sum(quantities)
```

тип `quantities`:

```go
[]int
```

Поэтому `T` определяется как `int`.

Функция на практике работает в смысле:

```go
func sum(values []int) int
```

Для второго вызова:

```go
sum(prices)
```

`T` будет `float64`:

```go
func sum(values []float64) float64
```

Важно, что функция не возвращает `any`. Какой тип использован на входе, такой же сохраняется и в результате.

Поэтому связи:

```go
[]int -> int
```

и:

```go
[]float64 -> float64
```

не теряются.

## Параметр типа и ограничение

После имени обобщённой функции внутри `[]` пишутся параметры типа.

Например:

```go
func sum[T Number](values []T) T
```

Разберём эту запись по частям.

### `T` — параметр типа

```go
T
```

здесь не конкретный тип.

Это имя для типа, который определяется при вызове функции.

Например, при вызове:

```go
sum([]int{1, 2, 3})
```

получаем:

```text
T = int
```

В следующем вызове:

```go
sum([]float64{1.5, 2.5})
```

получаем:

```text
T = float64
```

Имя `T` не обязательно. Можно использовать и другое имя:

```go
func sum[Element Number](values []Element) Element
```

Но для коротких параметров типа распространены имена вроде `T`, `K`, `V`, `R`.

### `Number` — ограничение

В части:

```go
T Number
```

`Number` — это ограничение (constraint).

Ограничение определяет, какие типы можно передать параметру типа.

В нашем примере написано:

```go
type Number interface {
	~int | ~int64 | ~float64
}
```

Значит, `T` может быть:

* `int`;
* `int64`;
* `float64`;
* или подходящим именованным типом, базовым типом (underlying type) которого является один из этих типов.

Ограничение определяет не только то, какие типы разрешены. Оно определяет и то, какие операции можно выполнять над значениями `T` внутри обобщённой функции.

Например, написано:

```go
total += value
```

На практике это означает:

```go
total = total + value
```

Все типы в ограничении `Number` поддерживают оператор `+`. Поэтому компилятор разрешает этот код.

Если бы в ограничении был тип, не поддерживающий оператор `+`, такой код написать было бы нельзя.

### `[]T` — обобщённый slice

Параметр функции записан как:

```go
values []T
```

Это значит, что `values` — slice, элементы которого имеют тип `T`.

Если:

```text
T = int
```

то:

```go
[]T
```

на практике будет:

```go
[]int
```

Если:

```text
T = float64
```

то:

```go
[]T
```

на практике будет:

```go
[]float64
```

### Последний `T` — тип возвращаемого значения

Буква:

```go
T
```

в конце сигнатуры функции обозначает тип возвращаемого значения:

```go
func sum[T Number](values []T) T
```

Это очень важно.

Какой тип элементов у входного slice, такой же тип будет и у результата функции.

Например:

```go
total := sum([]int{1, 2, 3})
```

здесь тип `total`:

```go
int
```

А в следующем:

```go
total := sum([]float64{1.2, 3.4})
```

тип `total`:

```go
float64
```

## Углубление: `|` и `~` в ограничениях

Для простых обобщённых функций может хватить `any` или готового ограничения. Приведённый ниже синтаксис наборов типов (type set) пригодится, когда нужно написать своё ограничение, охватывающее и именованные типы.

Ещё раз посмотрим на ограничение:

```go
type Number interface {
	~int | ~int64 | ~float64
}
```

Здесь два важных символа:

* `|`;
* `~`.

### `|` — объединение типов

Символ `|` объединяет несколько разрешённых наборов типов.

Например, если написать:

```go
int | float64
```

параметр типа может быть `int` или `float64`.

У нас написано:

```go
~int | ~int64 | ~float64
```

Значит, ограничение принимает значения, подходящие под эти три основные группы типов.

### `~` — соответствие базовому типу

`~int` означает не только сам встроенный тип `int`.

Он также принимает именованные типы, базовый тип которых — `int`.

Например:

```go
type Quantity int
```

Здесь `Quantity` — новый именованный тип.

Это не совсем тот же тип, что `int`:

```go
int
```

и:

```go
Quantity
```

— два отдельных типа.

Но базовый тип `Quantity` — `int`.

Поэтому ограничению:

```go
~int
```

подходит и `Quantity`.

Если бы ограничение было таким:

```go
type Number interface {
	int | float64
}
```

то разрешались бы только именно типы `int` и `float64`.

Следующий именованный тип:

```go
type Quantity int
```

ему бы не подошёл.

Поэтому `~` очень полезен в ограничениях, когда нужно поддерживать и именованные типы.

## Вывод типов

При вызове обобщённой функции аргумент типа можно указать вручную.

Например:

```go
total := sum[int]([]int{1, 2, 3})
```

Здесь через:

```go
[int]
```

мы сами указали, что `T` — именно `int`.

Полная логика:

```text
T = int
values = []int{1, 2, 3}
тип результата = int
```

Но во многих случаях Go может сам определить аргумент типа по аргументам функции.

Поэтому достаточно написать:

```go
total := sum([]int{1, 2, 3})
```

Компилятор видит аргумент `[]int`.

А функция имеет вид:

```go
func sum[T Number](values []T) T
```

Отсюда он определяет, что:

```text
[]T = []int
```

Значит:

```text
T = int
```

Этот процесс называется **выводом типов** (type inference).

Обе записи работают с одинаковым `T`:

```go
sum[int]([]int{1, 2, 3})
```

и:

```go
sum([]int{1, 2, 3})
```

Но второй вариант обычно короче и естественнее.

### Вывод типов работает не всегда

Иногда у компилятора недостаточно информации, чтобы определить `T`.

Например:

```go
func zero[T any]() T {
	var value T
	return value
}
```

Эта функция не принимает аргументов.

Если написать:

```go
zero()
```

компилятор не сможет понять, откуда узнать, какой тип у `T`.

Потому что функции не передано никакое значение, указывающее на:

* `int`;
* `string`;
* `bool`;
* или другой тип.

Поэтому аргумент типа нужно указать явно:

```go
num := zero[int]()
text := zero[string]()
```

В первом вызове:

```text
T = int
```

Во втором:

```text
T = string
```

## Ограничение `any`

`any` — одно из самых широких ограничений в Go.

Оно разрешает любой тип.

`any` на самом деле — псевдоним для:

```go
interface{}
```

То есть запись:

```go
T any
```

равна записи:

```go
T interface{}
```

Но в обобщённом коде `any` гораздо короче и легче читается.

Следующая функция создаёт копию slice:

```go
package main

import "fmt"

func clone[T any](values []T) []T {
	result := make([]T, len(values))
	copy(result, values)
	return result
}

func main() {
	numbers := clone([]int{10, 20, 30})
	words := clone([]string{"Go", "Generics"})

	fmt.Println(numbers)
	fmt.Println(words)
}
```

Результат:

```text
[10 20 30]
[Go Generics]
```

Эта функция не выполняет над самими элементами специфичных для типа операций вроде:

* сложения;
* вычитания;
* сравнения;
* сортировки.

Она только:

1. создаёт новый slice длиной как `[]T`;
2. копирует элементы через `copy()`;
3. возвращает новый `[]T`.

Поэтому дополнительное ограничение для `T` не нужно.

```go
T any
```

достаточно.

### `any` не разрешает все операторы

Здесь есть важное различие.

`any` означает:

> можно передать любой тип

Но не означает:

> можно использовать любой оператор

Например:

```go
func add[T any](a, b T) T {
	return a + b
}
```

такая функция не работает.

Причина в том, что `T` может быть любым типом.

Например, для:

```go
struct{}
```

или:

```go
[]int
```

оператора `+` не существует.

Точно так же:

```go
a > b
```

существует не для всех типов.

Поэтому с `T any` можно выполнять только операции, имеющие смысл для всех типов.

### Разница между обычным `any` и `T any`

Две следующие сигнатуры внешне похожи:

```go
func first(values []any) any
```

и:

```go
func first[T any](values []T) T
```

Но их смысл не одинаков.

Первый вариант:

```go
func first(values []any) any
```

не сохраняет связь с конкретным типом.

Функция принимает `any` и возвращает `any`.

Например, даже если результат на самом деле `int`, его статический тип будет `any`.

Второй вариант:

```go
func first[T any](values []T) T
```

сохраняет тип элементов входного slice.

Если передать:

```go
[]int
```

то:

```text
T = int
```

и результат тоже `int`.

Если передать:

```go
[]string
```

результат будет `string`.

Именно в этом одно из больших преимуществ generics: связь между типами сохраняется на этапе компиляции.

## Ограничение `comparable`

В некоторых обобщённых функциях значения нужно сравнивать через:

```go
==
```

или:

```go
!=
```

Для этого в Go есть готовое ограничение `comparable`.

Например:

```go
package main

import "fmt"

func contains[T comparable](values []T, target T) bool {
	for _, value := range values {
		if value == target {
			return true
		}
	}
	return false
}

func main() {
	fmt.Println(contains([]string{"go", "rust"}, "go"))
	fmt.Println(contains([]int{10, 20}, 30))
}
```

Результат:

```text
true
false
```

Функция работает так:

1. проходит по slice `values`;
2. сравнивает каждый элемент с `target`;
3. если найден равный элемент, возвращает `true`;
4. если весь slice проверен и подходящее значение не найдено, возвращает `false`.

Важная строка:

```go
if value == target
```

Здесь использован оператор `==`.

Поэтому компилятор должен знать, что `T` можно сравнивать через `==`.

По этой причине написано:

```go
T comparable
```

### Чего не означает `comparable`?

`comparable` означает, что значения можно сравнивать на равенство.

То есть можно использовать:

```go
==
```

и:

```go
!=
```

Но это не значит, что значения можно сравнивать по порядку.

Например, `comparable` недостаточно для:

```go
a < b
```

или:

```go
a > b
```

Потому что в `comparable` входят и такие типы, как `bool`, а `bool` не поддерживает оператор `<`.

Кроме того, не все типы Go являются `comparable`.

Например, значения типов:

* slice;
* map;
* function

нельзя сравнивать друг с другом обычным `==`.

Поэтому они не подходят под параметр типа `comparable`.

## Несколько параметров типа

Обобщённая функция не ограничена одним параметром типа.

Можно использовать несколько параметров типа.

Например, при работе с map типы ключа и значения могут различаться:

```go
map[string]int
```

Здесь:

```text
тип ключа = string
тип значения = int
```

Напишем обобщённую функцию, возвращающую ключи map в виде slice:

```go
package main

import "fmt"

func keys[K comparable, V any](items map[K]V) []K {
	result := make([]K, 0, len(items))
	for key := range items {
		result = append(result, key)
	}
	return result
}

func main() {
	ages := map[string]int{
		"Ali":  24,
		"Vali": 31,
	}

	fmt.Println(keys(ages))
}
```

Здесь два параметра типа:

```go
[K comparable, V any]
```

### `K` — тип ключа

```go
K comparable
```

`K` выражает тип ключа map.

В Go ключи map должны быть `comparable`.

Причина в том, что для поиска ключей в map Go должен проверять их на равенство.

Поэтому `K` нельзя сделать `any`. Если написать:

```go
K any
```

теоретически были бы разрешены и типы, которые не могут быть ключом map, например slice.

### `V` — тип значения

```go
V any
```

обозначает тип значения map.

Функция не выполняет над значениями `V` никаких специфичных для типа операций.

Она даже не читает значения.

Поэтому для `V` достаточно `any`.

### Тип результата

Функция возвращает:

```go
[]K
```

То есть какой тип у ключей map, такой же тип будет и у элементов результирующего slice.

Например, для:

```go
map[string]int
```

получаем:

```text
K = string
V = int
```

Результат:

```go
[]string
```

### О порядке map

Порядок итерации элементов map в Go не гарантирован.

Поэтому ключи, полученные через:

```go
for key := range items
```

не обязательно каждый раз выводятся в одном порядке.

Например, при одном запуске может вывестись:

```text
[Ali Vali]
```

При другом запуске может быть:

```text
[Vali Ali]
```

Если нужен точный порядок, ключи нужно потом отдельно отсортировать.

## Обобщённые типы

Параметры типа можно использовать не только в функциях, но и в объявлениях `type`.

Такой тип называется **обобщённым типом** (generic type).

Обобщённый тип полезен, чтобы использовать одну и ту же структуру данных с разными типами элементов.

Например, создадим `Stack`.

Стек работает по принципу LIFO:

```text
Last In, First Out
```

То есть последний добавленный элемент извлекается первым.

Код:

```go
package main

import "fmt"

type Stack[T any] struct {
	items []T
}

func (s *Stack[T]) Push(value T) {
	s.items = append(s.items, value)
}

func (s *Stack[T]) Pop() (T, bool) {
	if len(s.items) == 0 {
		var zero T
		return zero, false
	}

	last := len(s.items) - 1
	value := s.items[last]
	s.items = s.items[:last]
	return value, true
}

func main() {
	var stack Stack[string]
	stack.Push("первый")
	stack.Push("второй")

	value, ok := stack.Pop()
	if ok {
		fmt.Println(value)
	}
}
```

Результат:

```text
второй
```

### Как работает `Stack[T]`?

Структура объявлена так:

```go
type Stack[T any] struct {
	items []T
}
```

Здесь `T` обозначает тип элементов, хранящихся в стеке.

Например, если создать:

```go
Stack[string]
```

то:

```text
T = string
```

Поэтому `items` работает как:

```go
[]string
```

Если создать:

```go
Stack[int]
```

то:

```text
T = int
```

### `Push()`

Метод:

```go
func (s *Stack[T]) Push(value T) {
	s.items = append(s.items, value)
}
```

принимает только значение типа `T`.

Например, если:

```go
var stack Stack[string]
```

то:

```go
stack.Push("hello")
```

правильно.

А:

```go
stack.Push(10)
```

приводит к ошибке компиляции.

Потому что для `Stack[string]` `T` уже равен `string`.

### `Pop()`

Метод:

```go
func (s *Stack[T]) Pop() (T, bool)
```

возвращает два значения:

* элемент;
* `bool`, показывающий, есть ли элемент.

Сначала проверяется, пуст ли стек:

```go
if len(s.items) == 0 {
```

Если пуст, нужно вернуть обычное значение типа `T`.

Но `T` заранее неизвестен.

Поэтому используется приём, широко применяемый в обобщённом коде:

```go
var zero T
```

`zero` автоматически получает нулевое значение типа `T`.

Например:

```text
T = int       -> 0
T = string    -> ""
T = bool      -> false
T = *User     -> nil
```

Поэтому для пустого стека возвращается:

```go
return zero, false
```

### Извлечение последнего элемента

Если стек не пуст, последний индекс находится через:

```go
last := len(s.items) - 1
```

Например, если длина slice равна `2`:

```text
len = 2
last = 2 - 1
last = 1
```

Индексы:

```text
0 -> первый
1 -> второй
```

Поэтому:

```go
value := s.items[last]
```

берёт последний элемент.

Затем:

```go
s.items = s.items[:last]
```

удаляет этот элемент из стека.

### Получатель обобщённого типа

В методе обобщённого типа получатель тоже должен указывать параметр типа:

```go
func (s *Stack[T]) Push(value T)
```

Здесь:

```go
Stack[T]
```

говорит, что метод принадлежит обобщённому типу `Stack`.

Повторно писать ограничение в получателе не нужно.

Например, если структура объявлена как:

```go
type Stack[T any] struct
```

в методе не пишут:

```go
func (s *Stack[T any]) Push(...)
```

Правильная запись:

```go
func (s *Stack[T]) Push(...)
```

## Когда generics не нужны?

Generics дают мощную возможность. Но это не значит, что их нужно использовать везде.

В некоторых случаях обычная функция или интерфейс гораздо понятнее.

### Если код работает только с одним конкретным типом

Например, если функция должна работать только с `User`:

```go
func saveUser(user User)
```

просто сделать её обобщённой — пользы нет.

Запись вроде:

```go
func save[T User](value T)
```

может усложнить код, не дав практической пользы.

### Если типы требуют разного поведения

Generics удобны, когда один и тот же алгоритм работает на разных типах.

Если для каждого типа нужно совершенно разное поведение, внутри обобщённой функции может появиться много особых случаев.

В такой ситуации для полиморфизма лучшим решением может быть обычный интерфейс.

### Если интерфейс лучше выражает поведение

Например, если функции нужен:

> любой объект, умеющий делать `Write()`

естественнее использовать интерфейс, чем перечислять типы в ограничении.

Generics в основном полезны для того, чтобы:

> сохранять связь между конкретными типами значений на этапе компиляции

А интерфейс больше выражает поведение:

> что умеет объект

### Если обобщённый код усложняет чтение

Иногда ради небольшого сокращения дублирования пишется очень сложное ограничение.

В результате вместо простого кода из 5 строк может появиться трудночитаемая обобщённая абстракция.

В таком случае повторённый простой код иногда оказывается лучшим выбором.

### Выбирать ограничение как можно уже

Ограничение должно соответствовать возможностям, которые функции действительно нужны.

Например, если нужна только проверка на равенство:

```go
T comparable
```

достаточно.

Если не выполняется никаких специфичных для типа операций:

```go
T any
```

достаточно.

Если нужен `+`, нужен подходящий набор типов, поддерживающий `+`.

Добавление лишних типов в большое ограничение делает назначение функции неясным.

Чем точнее ограничение, тем понятнее, для чего предназначена обобщённая функция.

## Примеры

### 1. Получение нулевого значения любого типа

Этот пример показывает, как в обобщённом коде получить нулевое значение типа `T`.

Функция не принимает аргументов. Поэтому сам тип нужно явно указать при вызове.

```go
package main

import "fmt"

func zero[T any]() T {
	var value T
	return value
}

func main() {
	fmt.Println(zero[int]())
	fmt.Printf("%q\n", zero[string]())
	fmt.Println(zero[bool]())
}
```

Главная строка:

```go
var value T
```

В Go переменная, созданная через `var` без начального значения, автоматически получает нулевое значение своего типа.

Это правило работает и для обобщённого типа.

Для первого вызова:

```go
zero[int]()
```

имеем:

```text
T = int
```

Поэтому это работает как:

```go
var value int
```

Нулевое значение `int`:

```text
0
```

Для второго вызова:

```go
zero[string]()
```

имеем:

```text
T = string
```

Нулевое значение `string` — пустой текст:

```text
""
```

Для третьего вызова:

```go
zero[bool]()
```

результат:

```text
false
```

Поскольку функция не принимает аргументов, написать:

```go
zero()
```

недостаточно.

Компилятор не может определить `T` по аргументу.

Поэтому аргумент типа вроде:

```go
[int]
```

или:

```go
[string]
```

нужно указать явно.

Главное правило, показанное в этом примере: в обобщённом коде, чтобы получить нулевое значение неизвестного типа `T`, используется приём:

```go
var zero T
```

### 2. Безопасное получение первого элемента slice

Этот пример показывает, как безопасно обработать случай пустого slice при получении его первого элемента.

```go
package main

import "fmt"

func first[T any](values []T) (T, bool) {
	if len(values) == 0 {
		var zero T
		return zero, false
	}

	return values[0], true
}

func main() {
	number, numberOK := first([]int{10, 20, 30})
	word, wordOK := first([]string{})

	fmt.Println(number, numberOK)
	fmt.Printf("%q %t\n", word, wordOK)
}
```

Индексы slice начинаются с `0`.

Например, для:

```go
[]int{10, 20, 30}
```

индексы:

```text
0 -> 10
1 -> 20
2 -> 30
```

Поэтому первый элемент берётся через:

```go
values[0]
```

Но для пустого slice:

```go
[]string{}
```

индекса `0` не существует.

Если без проверки обратиться к:

```go
values[0]
```

программа вызовет panic во время выполнения.

Поэтому сначала проверяется:

```go
if len(values) == 0
```

Если пуст, возвращается:

```go
var zero T
return zero, false
```

Здесь `false` означает:

> элемент не найден

Если элемент есть, возвращается:

```go
return values[0], true
```

Результат первого вызова:

```go
first([]int{10, 20, 30})
```

равен:

```text
10 true
```

Во втором вызове slice пуст:

```go
first([]string{})
```

поэтому возвращается:

```text
"" false
```

Этот приём похож на стиль `value, ok`, встречающийся во многих API Go.

### 3. Разворот slice на месте

В этом примере одна обобщённая функция разворачивает порядок slice с элементами `int`, `string` или любого другого типа.

```go
package main

import "fmt"

func reverse[T any](values []T) {
	for left, right := 0, len(values)-1; left < right; left, right = left+1, right-1 {
		values[left], values[right] = values[right], values[left]
	}
}

func main() {
	numbers := []int{1, 2, 3, 4}
	words := []string{"один", "два", "три"}

	reverse(numbers)
	reverse(words)

	fmt.Println(numbers)
	fmt.Println(words)
}
```

Этот алгоритм одновременно идёт с начала и с конца slice.

В начале:

```go
left := 0
```

обозначает индекс первого элемента.

```go
right := len(values) - 1
```

обозначает индекс последнего элемента.

Например, для:

```go
numbers := []int{1, 2, 3, 4}
```

имеем:

```text
len(numbers) = 4
right = 4 - 1
right = 3
```

Индексы:

```text
0 -> 1
1 -> 2
2 -> 3
3 -> 4
```

На первой итерации:

```text
left = 0
right = 3
```

выполняется обмен:

```go
values[left], values[right] = values[right], values[left]
```

Результат:

```text
[4 2 3 1]
```

Затем:

```text
left = 1
right = 2
```

Снова обмен:

```text
[4 3 2 1]
```

Затем индексы встречаются, и условие:

```go
left < right
```

больше не выполняется.

Функция не выполняет над элементами:

* арифметических операций;
* проверок на равенство;
* сравнений по порядку.

Она только меняет элементы местами.

Поэтому:

```go
T any
```

достаточно.

Функция не возвращает новый slice.

Она изменяет элементы переданного slice на месте.

### 4. Удаление повторяющихся значений

Этот пример показывает ещё одно важное применение ограничения `comparable`.

Значения используются как ключи map.

```go
package main

import "fmt"

func unique[T comparable](values []T) []T {
	seen := make(map[T]bool)
	result := make([]T, 0, len(values))

	for _, value := range values {
		if !seen[value] {
			seen[value] = true
			result = append(result, value)
		}
	}

	return result
}

func main() {
	fmt.Println(unique([]int{2, 2, 3, 2, 4, 3}))
	fmt.Println(unique([]string{"go", "api", "go"}))
}
```

Map `seen`:

```go
seen := make(map[T]bool)
```

хранит уже встретившиеся значения.

Ключ map имеет тип `T`.

Ключи map в Go должны быть `comparable`.

Поэтому функция использует ограничение:

```go
T comparable
```

Разберём процесс для первого slice:

```text
[2, 2, 3, 2, 4, 3]
```

Для первого `2`:

```go
seen[2]
```

ещё `false`.

Поэтому выполняется:

```go
seen[2] = true
```

и `2` добавляется в результат.

Результат:

```text
[2]
```

Когда приходит следующее `2`:

```go
seen[2] == true
```

Поэтому оно не добавляется повторно.

Когда `3` приходит впервые, оно добавляется в результат:

```text
[2 3]
```

`4` тоже добавляется:

```text
[2 3 4]
```

Последнее `3` пропускается, потому что встречалось раньше.

`result` создан так:

```go
result := make([]T, 0, len(values))
```

Здесь длина:

```text
0
```

Потому что в начале ещё не добавлено ни одного уникального элемента.

Ёмкость берётся равной:

```go
len(values)
```

Причина в том, что в худшем случае все элементы могут быть уникальными.

Например, для:

```text
[1 2 3 4]
```

результат тоже состоит из 4 элементов.

### 5. Выбор меньшего из двух значений

В этом примере обобщённое ограничение принимает только определённые числовые типы.

Внутри функции используется оператор `<`.

```go
package main

import "fmt"

type OrderedNumber interface {
	~int | ~int64 | ~float64
}

func min[T OrderedNumber](a, b T) T {
	if a < b {
		return a
	}
	return b
}

func main() {
	fmt.Println(min(8, 3))
	fmt.Println(min(4.5, 7.2))
}
```

Ограничение записано так:

```go
type OrderedNumber interface {
	~int | ~int64 | ~float64
}
```

Все эти типы поддерживают оператор `<`.

Поэтому внутри обобщённой функции можно написать:

```go
if a < b
```

Для первого вызова:

```go
min(8, 3)
```

компилятор определяет, что:

```text
T = int
```

Проверка:

```text
8 < 3 -> false
```

Поэтому возвращается:

```text
3
```

Для второго вызова:

```go
min(4.5, 7.2)
```

имеем:

```text
T = float64
```

Проверка:

```text
4.5 < 7.2 -> true
```

Результат:

```text
4.5
```

Здесь оба аргумента имеют одинаковый тип `T`.

Результат тоже именно `T`.

Поэтому связь типов сохраняется.

`comparable` для этой функции было бы недостаточно. Причина в том, что `comparable` гарантирует только `==` и `!=`, но не `<`.

### 6. Суммирование именованного числового типа

Этот пример показывает, зачем нужен символ `~` в ограничении.

```go
package main

import "fmt"

type Addable interface {
	~int | ~float64
}

type Distance int

func sum[T Addable](values []T) T {
	var total T
	for _, value := range values {
		total += value
	}
	return total
}

func main() {
	distances := []Distance{12, 8, 15}
	prices := []float64{10.5, 4.25}

	fmt.Println(sum(distances))
	fmt.Println(sum(prices))
}
```

Здесь:

```go
type Distance int
```

создаёт новый именованный тип.

`Distance` — это не совсем `int`.

Но его базовый тип — `int`.

В ограничении написано:

```go
~int
```

Поэтому `Distance` тоже подходит под ограничение `Addable`.

Если бы ограничение имело вид:

```go
type Addable interface {
	int | float64
}
```

`Distance` бы не подошёл.

Внутри `sum()` написано:

```go
var total T
```

Если:

```text
T = Distance
```

то `total` получает нулевое значение типа `Distance`.

Поскольку базовый тип `Distance` — `int`, нулевое значение:

```text
0
```

Затем значения складываются по очереди:

```text
0 + 12 = 12
12 + 8 = 20
20 + 15 = 35
```

Результат:

```text
35
```

Для `prices`:

```text
0 + 10.5 = 10.5
10.5 + 4.25 = 14.75
```

Результат:

```text
14.75
```

Начинать сумму с `0` правильно, потому что прибавление `0` не меняет результат.

### 7. Преобразование элементов slice в другой тип

Этот пример показывает, как два разных параметра типа работают в одной функции.

Входной элемент может быть одного типа, а результат — другого.

```go
package main

import "fmt"

func transform[T any, R any](values []T, convert func(T) R) []R {
	result := make([]R, 0, len(values))
	for _, value := range values {
		result = append(result, convert(value))
	}
	return result
}

func main() {
	numbers := []int{3, 5, 8}
	labels := transform(numbers, func(value int) string {
		return fmt.Sprintf("num=%d", value)
	})

	fmt.Println(labels)
}
```

Функция принимает два параметра типа:

```go
[T any, R any]
```

`T` — тип входного элемента.

`R` — тип элемента результата.

В нашем примере передано:

```go
numbers := []int{3, 5, 8}
```

Поэтому:

```text
T = int
```

Функция `convert` имеет вид:

```go
func(value int) string
```

Значит:

```text
R = string
```

Поэтому `transform()` на практике выполняет преобразование:

```text
[]int -> []string
```

Процесс:

```text
3 -> "num=3"
5 -> "num=5"
8 -> "num=8"
```

Результат:

```text
[num=3 num=5 num=8]
```

Результирующий slice создаётся через:

```go
result := make([]R, 0, len(values))
```

Его длина в начале `0`, потому что результатов ещё нет.

Ёмкость равна длине входного slice.

Причина в том, что для каждого входного элемента создаётся по одному результату.

Например, если в `values` 3 элемента, в итоговом `result` тоже будет 3 элемента.

Этот шаблон похож на операцию, которую в других языках часто называют `map` или `transform`.

### 8. Отбор элементов, подходящих под условие

В этом примере обобщённая функция сама не проверяет элементы.

Правило проверки передаётся через отдельную функцию.

```go
package main

import "fmt"

func filter[T any](values []T, keep func(T) bool) []T {
	result := make([]T, 0, len(values))
	for _, value := range values {
		if keep(value) {
			result = append(result, value)
		}
	}
	return result
}

func main() {
	even := filter([]int{1, 2, 3, 4, 5, 6}, func(value int) bool {
		return value%2 == 0
	})
	long := filter([]string{"Go", "api", "generics"}, func(value string) bool {
		return len(value) >= 3
	})

	fmt.Println(even)
	fmt.Println(long)
}
```

Сама `filter()` не имеет никаких особых знаний о значении `T`.

Она смотрит только на результат:

```go
keep(value)
```

Если возвращается `true`, элемент добавляется в результат через:

```go
result = append(result, value)
```

Если возвращается `false`, элемент пропускается.

В первом примере:

```go
value%2 == 0
```

определяет чётные числа.

Значения:

```text
1 -> false
2 -> true
3 -> false
4 -> true
5 -> false
6 -> true
```

Результат:

```text
[2 4 6]
```

Во втором примере:

```go
len(value) >= 3
```

проверяет длину строки.

Значения:

```text
"Go"       -> 2 -> false
"api"      -> 3 -> true
"generics" -> 8 -> true
```

Результат:

```text
[api generics]
```

Обратите внимание, что здесь использовано:

```go
>= 3
```

Значит, берётся и значение длиной ровно `3`.

Если бы было написано:

```go
> 3
```

`"api"` не попало бы в результат.

Поскольку в самой `filter()` не используется специфичный для типа оператор:

```go
T any
```

достаточно.

### 9. Хранение значений двух разных типов в одной структуре

У обобщённого типа тоже может быть несколько параметров типа.

В этом примере `Pair` хранит вместе два разных значения.

```go
package main

import "fmt"

type Pair[K any, V any] struct {
	Key   K
	Value V
}

func main() {
	stock := Pair[string, int]{Key: "тетрадь", Value: 25}
	point := Pair[int, float64]{Key: 7, Value: 18.5}

	fmt.Println(stock.Key, stock.Value)
	fmt.Println(point.Key, point.Value)
}
```

Объявление структуры:

```go
type Pair[K any, V any] struct
```

имеет два независимых параметра типа.

`K` и `V` не обязаны быть одного типа.

Для первого значения:

```go
Pair[string, int]
```

имеем:

```text
K = string
V = int
```

Поэтому это работает как:

```go
Key string
Value int
```

Для второго значения:

```go
Pair[int, float64]
```

имеем:

```text
K = int
V = float64
```

На этот раз структура на практике имеет поля:

```go
Key   int
Value float64
```

Внутри структуры над значениями не выполняются операции:

* равенства;
* арифметики;
* упорядочивания.

Поэтому для обоих параметров типа:

```go
any
```

достаточно.

Этот обобщённый тип показывает, что одну и ту же структуру данных можно переиспользовать с разными сочетаниями типов.

### 10. Создание обобщённой очереди

В этом примере создаётся обобщённая `Queue`.

Очередь работает по принципу FIFO:

```text
First In, First Out
```

То есть первый добавленный элемент извлекается первым.

```go
package main

import "fmt"

type Queue[T any] struct {
	items []T
}

func (q *Queue[T]) Add(value T) {
	q.items = append(q.items, value)
}

func (q *Queue[T]) Remove() (T, bool) {
	if len(q.items) == 0 {
		var zero T
		return zero, false
	}

	value := q.items[0]
	q.items = q.items[1:]
	return value, true
}

func main() {
	var queue Queue[string]
	queue.Add("первый")
	queue.Add("второй")

	first, firstOK := queue.Remove()
	second, secondOK := queue.Remove()
	emptyValue, emptyOK := queue.Remove()

	fmt.Println(first, firstOK)
	fmt.Println(second, secondOK)
	fmt.Printf("%q %t\n", emptyValue, emptyOK)
}
```

Очередь создана так:

```go
type Queue[T any] struct {
	items []T
}
```

`T` обозначает тип элементов, хранящихся в очереди.

У нас написано:

```go
var queue Queue[string]
```

Значит:

```text
T = string
```

### Добавление элемента

```go
func (q *Queue[T]) Add(value T) {
	q.items = append(q.items, value)
}
```

`Add()` добавляет новый элемент в конец slice.

Сначала:

```go
queue.Add("первый")
```

Результат:

```text
["первый"]
```

Затем:

```go
queue.Add("второй")
```

Результат:

```text
["первый", "второй"]
```

### Извлечение элемента

Из очереди должен извлекаться самый старый элемент.

Самый старый элемент находится в начале slice, то есть по индексу `0`:

```go
value := q.items[0]
```

Первый `Remove()`:

```text
value = "первый"
```

Затем выполняется:

```go
q.items = q.items[1:]
```

Это убирает элемент с индексом `0` из нового представления slice.

В результате остаётся:

```text
["второй"]
```

Второй `Remove()`:

```text
value = "второй"
```

Затем очередь становится пустой.

### Случай пустой очереди

Когда в третий раз вызывается:

```go
queue.Remove()
```

выполняется условие:

```go
len(q.items) == 0
```

Поэтому срабатывает:

```go
var zero T
return zero, false
```

Здесь:

```text
T = string
```

Поэтому нулевое значение `string`:

```text
""
```

Результат:

```text
"" false
```

`false` означает, что в очереди нет элементов.

В этом примере одновременно видны несколько правил generics:

* обобщённый тип;
* метод обобщённого типа;
* запись `Queue[T]` в получателе;
* получение нулевого значения `T`;
* свободный выбор типа элементов через `T any`;
* после создания `Queue[string]` методы работают только со `string`.

## Тестирование обобщённого кода

Обобщённая функция может работать с несколькими типами. Поэтому в тестах полезно отдельно проверять нужные варианты типов.

```go
package main

import "testing"

type Number interface {
	~int | ~float64
}

func max[T Number](a, b T) T {
	if a > b {
		return a
	}

	return b
}

func TestMax(t *testing.T) {
	t.Run("int", func(t *testing.T) {
		if got := max(4, 9); got != 9 {
			t.Errorf("max(4, 9) = %d; ожидалось 9", got)
		}
	})

	t.Run("float64", func(t *testing.T) {
		if got := max(7.5, 2.5); got != 7.5 {
			t.Errorf("max(7.5, 2.5) = %g; ожидалось 7.5", got)
		}
	})
}
```

Два подтеста проверяют одну и ту же обобщённую функцию со значениями `int` и `float64`. Компилятор определяет тип `T` по аргументам каждого вызова. Тесты можно запустить как обычно следующей командой:

```bash
go test ./...
```
